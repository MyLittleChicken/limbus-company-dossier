# 데이터 모델 (Data Model)

> 상태: 초안 v0.1 / 최종 수정 2026-07-25
> 1단계(데이터베이스 구축) 착수 전 문서. **정보 제공에 필요한 엔티티의 구조**를 정의한다.
> 추천에 필요한 파생 필드와 관계 정의는 `06-recommendation-engine.md`에서 다룬다.
> 수량과 필드는 `01-data-source.md`의 소스를 실제로 확인한 결과에 근거하며, 2026-07-25 스냅샷 기준이다.

## 1. 설계 원칙

1. **정적 게임 데이터만 다룬다.** 사용자가 만들어내는 데이터(런 기록 등)는 4단계 문서에서 정의한다.
2. **파생 값은 저장하지 않는다.** 팀 키워드 집계처럼 계산으로 얻을 수 있는 값은 엔티티에 두지 않는다.
3. **식별자는 원본 게임 id를 유지한다.** 자체 id를 새로 부여하지 않는다. 소스 간 조인과 패치 대응이 id에 의존한다.
4. **표시 문자열을 엔티티에서 분리한다.** 엔티티는 id로 참조하고, 이름·설명은 로케일별로 분리해 보관한다.
5. **모든 데이터셋은 기준 게임 버전을 명시한다.**

## 3. 엔티티 정의

### 3.1 수감자 (Sinner)

12명 고정. 인격과 E.G.O의 소속 주체다.

| 필드 | 설명 |
| --- | --- |
| id | 1–12 |
| name | 표시명 (로케일 분리) |

### 3.2 인격 (Identity)

| 필드 | 설명 |
| --- | --- |
| id | 원본 게임 id. 기본 인격은 `1{수감자번호:02}01` 규칙을 따른다 |
| sinnerId | 소속 수감자 |
| name | 표시명. 한국어 원본에서는 `title`이 인격명이고 `name`은 수감자명이다 |
| rarity | 1–3 (게임 표기 0 / 00 / 000) |
| season | 출시 시즌 |
| releaseDate | 출시일 |
| skills | 스킬 목록 (3.3) |
| defenseSkills | 방어 스킬 목록 |
| hp / speed / resists / defCorrection | 스탯과 저항 |
| affiliations | 소속 태그 목록 (3.11) |
| statuses | 보유 상태 목록 |

### 3.3 스킬 (Skill)

인격에 종속한다. 독립 조회 대상이 아니다.

| 필드 | 설명 |
| --- | --- |
| id | 원본 스킬 id |
| slot | S1 / S2 / S3 / 방어 / E.G.O |
| deckCount | 덱 매수. S1은 3, S2는 2, S3은 1 |
| sin | 죄악 속성 (4.1) |
| attackType | 공격 타입 (4.2). 방어 스킬은 guard / evade / counter |
| coins | 코인 목록. 코인 하나가 원소 하나다 |
| coinValue / baseValue / atkWeight | 위력 관련 수치 |
| inflicts | 부여하는 상태와 수치 |
| uptie | 1–4 단계별 값 |

**주의 사항**

- 소스의 `num` 필드는 **코인 수가 아니라 덱 매수**다. 코인 정보는 인격별 상세 파일에만 있다.
- **코인 수에 상한을 두지 않는다.** 실측 분포는 1–5개이며 9개인 사례가 1건 있다.
- uptie 데이터는 **1→4 델타**로 저장되어 있다. 앞 단계부터 병합해야 최종값이 나온다.

### 3.4 E.G.O

| 필드 | 설명 |
| --- | --- |
| id | 원본 게임 id |
| sinnerId | 소속 수감자 |
| name / desc | 표시명과 설명 |
| rank | 등급 (4.4) |
| cost | **죄악 자원 소모량.** 속성별 수량 (예: 나태 3, 분노 1) |
| awakeningType | 각성 시 죄악 속성과 공격 타입 |
| corrosionType | 침식 시 속성 |
| resists / statuses | 저항과 보유 상태 |
| passives | 상시 효과 목록 |
| extractable / maxThreadspin | 추출·실뽑기 관련 |

**주의 사항**

- **패시브는 요약 파일에 없다.** 개별 상세 파일에만 존재한다.
- `cost`는 E.G.O 기능의 핵심이다. 죄악 자원은 해당 속성 스킬로 수급되므로, 정보 제공 화면에서 **공급(팀 스킬의 죄악 속성 분포)과 수요(장착 E.G.O의 cost 합)** 를 함께 보여줄 근거가 된다.

### 3.5 E.G.O 기프트 (Gift)

거울 던전에서 획득하는 강화 요소다. 정보 제공의 중심 엔티티다.

| 필드 | 설명 |
| --- | --- |
| id | 원본 게임 id |
| name | 표시명. 강화 단계별로 이름이 다르다 |
| desc | 설명문. 정제된 텍스트를 사용한다 |
| tier | 등급 (4.5) |
| keyword | 연관 키워드. 상태 키워드 또는 공격 타입이며, 없는 경우도 있다 |
| affinity | 죄악 속성 |
| enhanceable | 강화 가능 여부 |
| enhanceLevel | 강화 단계 |
| exclusiveTo | 전용 테마 팩. 없으면 범용 풀에서 등장한다 |
| recipes | 합성 레시피 (3.6) |
| mdCost | 거울 던전 내 획득 비용 |

**주의 사항**

- 456종 중 **팩 전용은 230종**이고 나머지 226종은 범용 풀이다. `exclusiveTo`가 비어 있는 것은 결손이 아니다.
- `keyword` 축에는 상태 키워드뿐 아니라 **공격 타입(참격·관통·타격)이 60종** 포함된다. 키워드 없는 기프트도 120종 있다.
- 강화 단계별로 별도 id가 부여된다(예: 9001 / 19001 / 29001). 같은 기프트의 다른 단계로 묶어야 한다.

### 3.6 합성 레시피 (FusionRecipe)

| 필드 | 설명 |
| --- | --- |
| id | 레시피 식별자 |
| resultGiftId | 결과 기프트 |
| materials | 재료 목록. 각 재료는 기프트 id, 수량, 대체 가능 여부를 갖는다 |

재료가 그룹으로 묶이며, 같은 그룹 안에서 대체 가능한 재료가 있을 수 있다.

### 3.7 테마 팩 (Pack)

층 진입 시 선택하는 단위다. 추천의 최종 대상이다.

| 필드 | 설명 |
| --- | --- |
| id | 원본 게임 id |
| name | 표시명 |
| category | 팩 분류 — `canto` / `event` / `extreme` 등 |
| variant | 변형 구분 (`normal` 등) |
| chapter | 소속 장 |
| sprite | 이미지 파일 키. 애셋은 id가 아니라 이 값으로 찾는다 |
| normalFloors / hardFloors | 난이도별 등장 층 |
| superposition / extreme | 중첩·극한 팩 여부 |
| gifts | 이 팩에서 등장하는 기프트 전체 목록 |
| exclusiveGifts | 이 팩에서만 나오는 기프트 |
| bossEncounters | 등장 보스 |

117종 중 **71종이 전용 기프트를 갖는다.** 기프트의 `exclusiveTo`와 팩의 `exclusiveGifts`는 상호 참조 관계이며,
소스에서 두 값의 교차 무결성이 확인되었다(불일치 0).

층 정보가 없는 팩이 21종 있다. 20종은 `extreme` 분류이고 1종은 이벤트 팩으로, 일반 층 순환에 등장하지 않는다.

### 3.8 거울 던전 (MirrorDungeon)

| 필드 | 설명 |
| --- | --- |
| version | 거울 던전 버전 |
| name | 버전 명칭 |
| releaseDate | 적용 시점 |
| totalFloors | 전체 층 수 |
| baseFloors | 기본 층 수 |
| tierFloors | 난이도 등급별 층 구간 |

확인된 구성은 전체 **15층**, 기본 5층이며, 등급별 구간은 `normal` 1–5 · `hard` 1–5 · `superposition` 6–10 · `extreme` 11–15이다.
즉 다른 문서의 "15층"은 전체 층수를 가리키며, 후반 층일수록 상위 등급 팩이 배정된다.

거울 던전은 버전마다 구성이 바뀐다. 데이터셋은 **한 시점의 한 버전**을 담으며 버전을 명시한다.

### 3.9 층별 등장 팩 (FloorPackTable)

| 필드 | 설명 |
| --- | --- |
| difficulty | 난이도 |
| floorRange | 층 또는 층 구간 |
| packIds | 해당 구간에서 등장하는 팩 목록 |

소스의 테이블은 **난이도별로 층 구간 단위**로 정의되어 있다.
확인된 구조는 hard가 1, 2, 3, 4, 5, 6–10, 11–15 구간이고 normal이 1–5다.
"이번 층에 어떤 팩이 나오는가"의 판단 근거가 되는 실데이터다.

### 3.10 상태 (Status)

기프트와 스킬이 다루는 상태다. 표시 키워드와 내부 식별자가 다르므로 대응표가 필요하다(4.3).

| 필드 | 설명 |
| --- | --- |
| id | 내부 상태 id |
| name | 표시명 |
| side | 적용 대상 (적 / 아군) |
| kind | 성격 (상태이상 / 자원 등) |

**상태 판정은 이름 매칭이 아니라 상태 목록의 메타데이터로 한다.** 이름 매칭은 오탐한다.

### 3.11 소속 (Affiliation)

인격 필터링에 사용하는 태그다. 93종.

| 필드 | 설명 |
| --- | --- |
| id | 원본 영문 태그 |
| name | 한국어 표시명 |

**필터 키는 원본 영문 태그를 유지하고 표시만 한국어로 한다.** 조인 안정성 때문이다.
한국어 표시명은 90종까지 확보되었고, 나머지 3종은 소스에 없어 영문을 그대로 노출한다.
태그 값에 스포일러 마크업이 섞여 있어 정제가 필요하다.

## 4. 열거값

### 4.1 죄악 속성 (7)

분노 · 색욕 · 나태 · 탐식 · 우울 · 오만 · 질투

### 4.2 공격 타입 (3)

참격 · 관통 · 타격

방어 스킬은 별도로 방어 · 회피 · 반격으로 구분된다.

### 4.3 상태 키워드 (7)

| 표시명 | 내부 식별자 | 대상 |
| --- | --- | --- |
| 출혈 | Laceration | 적 |
| 화상 | Combustion | 적 |
| 진동 | Vibration | 적 |
| 파열 | Burst | 적 |
| 침잠 | Sinking | 적 |
| 호흡 | Breath | 아군 |
| 충전 | Charge | 아군 |

내부 식별자와 표시명이 일치하지 않으므로 대응표 없이 문자열을 매칭하면 안 된다.
설명문에 남아 있는 `[내부식별자]` 토큰은 별도 표기 파일로 치환해야 읽을 수 있다.

기프트의 연관 키워드는 위 7종에 공격 타입 3종(참격·관통·타격)을 더한 **10종을 하나의 축**으로 다룬다.
출처 데이터의 정렬 순서는 화상 · 출혈 · 진동 · 파열 · 침잠 · 호흡 · 충전 · 참격 · 관통 · 타격이다.

### 4.4 E.G.O 등급

ZAYIN · TETH · HE · WAW · ALEPH 5종. 등급 순서는 이 순이다.

### 4.5 기프트 등급

1–5 및 EX.

## 5. 관계

```
Sinner 1 ─── N Identity 1 ─── N Skill
Sinner 1 ─── N E.G.O

Skill        N ─── M Status      (부여하는 상태)
E.G.O        N ─── M Status      (패시브가 다루는 상태)
Identity     N ─── M Affiliation

Gift         N ─── 1 Status      (연관 키워드, 없을 수 있음)
Gift         N ─── M Gift        (합성 레시피의 재료 ─ 결과)
Gift         N ─── M Pack        (전용 기프트. 범용 기프트는 관계 없음)

Pack         N ─── M FloorPackTable
MirrorDungeon 1 ─── N FloorPackTable
```

## 6. 식별자와 표시명

- 모든 엔티티는 **원본 게임 id**를 기본 키로 쓴다.
- 표시명과 설명은 한국어를 정본으로 하되, 소스에 한국어가 없는 항목은 영문을 유지한다. **없는 표기를 만들어내지 않는다.**
- 표시용 텍스트와 파싱용 원문을 분리해 보관한다. 원문에는 내부 식별자와 마커가 남아 있다.

## 7. 버전 관리

데이터셋 전체에 기준 게임 버전과 거울 던전 버전을 스탬프로 남긴다.
버전이 다른 데이터를 한 데이터셋에 섞지 않는다.

## 8. 미결

- 팩의 기프트 제공이 고정인지 확률 풀인지. 팩별 기프트 목록은 확보했으나 등장 확률은 확인되지 않았다.
- 방어 스킬과 E.G.O를 정보 제공 범위에 어느 수준까지 포함할지.
- 이미지 애셋을 엔티티에 연결할지 여부(`01-data-source.md` 8절과 연동).
- 인격 스킬 13종의 아이콘이 확보되지 않았다. 대체 표시 방식이 필요하다(`04-data-inventory.md` 7절).
