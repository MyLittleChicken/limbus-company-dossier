# MVP 최종 검수 — 2026-09-08

상태: **감사 최종 검수 완료 · 제품 출시 보류**. design/data 보고서를 대조하고 부족한 근거를 재요청했다. 아래 게이트·DB·체크섬 결과는 ops가 직접 실행해 확인했다.

> **감사 후 사용자 방향 확정:** “종합 정보 도감이 최우선 MVP.” 아래의 정보12종/용어 제외 및 고정 스냅샷 출시는 감사 당시 제안이며 최종 화면 범위 승인이 아니다. 현재는 인격·E.G.O·기프트·팩을 동등한 핵심으로 두고 용어 유지, 편성·추천 분리를 사용자와 논의 중이다. 최신 데이터 누락 여부도 추가 조사하여 보완 출처에서 인격1·E.G.O2의 신규 ID를 확인했다. 페이지/ETL 갱신 구현은 이 감사로 수행하지 않았다.

## 결론

**정보 조회용 로컬 알파는 동작하지만, 초기 제품의 출시 승인은 보류한다.**
디자인이 구현된 화면과 데이터 정확성·복원 가능성·운영 준비는 별도 기준이다.
이번 임무는 현재 페이지 분류, 데이터 완성도, ETL 점검이며 전체 화면 재설계나 공개 배포를 완료했다는 뜻이 아니다.

MVP 기준은 **MD7 / 2026-07-25 스냅샷의 정보 조회 사이트**로 잡는다.
인격·E.G.O·기프트·팩 목록과 상세, 홈·층·거울 던전·고지의 12종이 대상이다.
편성·추천·용어 3종은 이번 출시 범위에서 제외하는 방향으로 제품 표면과 문서를 정리해야 한다.
추천은 고정 덱 시연이며 사용자 맞춤 추천 제품으로 표시하지 않는다.
서버 덱 저장·로그인·실시간 게임 패치 추종·트래커·새 추천 모델은 이번 MVP에 넣지 않는다.
이 기준은 이번 점검의 출시 기준이며, 기존 제안 문서와 실제 라우트 변경은 아직 수행하지 않았다.

로케일별 템플릿 15종 + 실제 루트 리다이렉트 1개다. ko/en은 중복 계산하지 않는다.

| 분류 | 수 | 페이지 (`/[locale]` 생략) |
| --- | ---: | --- |
| 새 디자인 구현 | 6 | 인격 목록·상세, E.G.O 목록·상세, 기프트 목록, 팩 목록 |
| 구판·부분 완성 | 6 | 홈, 기프트 상세, 팩 상세, 층, 거울 던전, 고지 |

구판도 본문·강화 단계·관계 링크는 구현되어 있다. 외형을 전부 다시 만드는 것보다 정보 오류와 핵심 동선 수정을 우선한다.
9월 7일 제안의 “11종/새 디자인 7종”은 실제 목록과 맞지 않는다. `/lab/*` 이전도 아직 구현되지 않았다.

## 2. 데이터 완성도

기존 DB의 실측을 가장하지 않기 위해 별도 빈 DB에 현재 로컬 원본과 저장소의 저작 데이터를 적재했다.

| 엔티티 | 화면 대상 | canonical 전체 | 화면 대상 한·영 이름 누락 | 대표 이미지 경로 누락 |
| --- | ---: | ---: | ---: | ---: |
| 인격 | 184 | 184 | 0 | 0 |
| E.G.O | 110 | 115 | 0 | 0 |
| 거울 던전 기프트 | 456 | 582 | 0 | 0 |
| 팩 | 117 | 117 | 0 | 0 |

- 114테이블: raw 4 / canonical 100 / app 10.
- 기본키 중복 그룹 0, 외래키 99개 전수 조회의 고아 참조 0, field_source의 없는 snapshot 참조 0.
- `field_gap` 1,272건. 필드·언어·사유별 기록이며 “1,272개 엔티티가 불완전”하거나 전체 데이터의 결손율을 뜻하지 않는다.
- 홈은 전체 적재 수(E.G.O 115·기프트 582)를 표시하지만 목록은 110·456을 보여준다. 홈 진입 카드에는 같은 조회 범위의 개수를 써야 한다. 고지의 전체 적재 수와는 구분한다.
- 명칭·대표 이미지의 존재와 관계 무결성은 확인했지만, 모든 효과의 의미·현재 게임과의 일치·부가 이미지 전체·번역의 의미 정확성을 보증하지 않는다.
- 스냅샷은 점검일보다 45일 전이다. 최신 패치 데이터라고 표시할 수 없다. 이번 MVP는 고정 스냅샷임을 화면에 분명히 밝히는 방식이다.
- ops 독립 체크섬 대조: entities 1,666/1,666 일치, assets 4,737 중 4,721 일치·16개 없음·존재 파일 불일치 0. 없는 16개는 `v1-local` 부가 아이콘이며 위 네 엔티티의 대표 이미지 경로 검사와는 별도다.

## 3. ETL 판정

실행한 초기 적재 순서는 **DDL → raw → authored seed → canonical → 검증**이다.
raw는 1,664파일에서 43,270행, authored gift ability는 1,295행을 적재했다.
manifest 파일 검증 개수와 raw 스캔 대상 개수는 다른 집합이므로 같은 수치로 쓰지 않는다.

| 게이트 | 이번 결과 | 판정 |
| --- | --- | --- |
| raw 검증 | 13/13 통과 | 적재 수·기록된 출처 기준 통과 |
| canonical 검증 | 250개 중 246 통과 / 4 실패 | 출시 게이트 실패 |
| 단위·DB 골든 테스트 | 703/703 통과, skip 0 | 테스트가 다루는 범위 통과 |
| 타입 검사 | 최초 19개 오류 → 수정 후 통과 | 수정 검수 완료 |
| 프로덕션 빌드 | 최초 및 타입 수정 후 모두 통과 | DB 정상 동작을 대신 증명하지 않음 |
| Prisma 스키마 및 DDL 드리프트 | validate 통과, 생성 SQL 일치 | 통과 |
| 원격 전체 재수집·승격·롤백·재현 해시 | 이번 회차 미실행 | 기존 문서의 과거 결과를 현재 합격으로 사용하지 않음 |

canonical 실패 4건의 원인은 다음과 같다.

1. **키워드 순서 유실:** `readSource()`가 정렬/원본 위치 없이 raw를 읽고, `buildVocab()`가 Map 순회를 원본 순서로 해석한다. `None.order` 실측 6, 기대 원본 위치 11. DB 반환 순서는 보장되지 않으므로 테스트 기대값을 6으로 바꾸는 방식은 부적절하다.
2. **기존 값 보정의 복원 누락:** ADR-07에 기록된 기프트 9212·9249·9427·9428·9431의 `hardOnly=false` 보정이 빈 app DB의 seed에 없다. hardOnly 전체 수 122/기대117 및 개별 5건 검증, 총 2개 게이트가 실패한다. 승인된 보정을 복원 가능한 저작 입력으로 포함해야 한다.
3. **dirty 출처 게이트:** 사용자 기존 미커밋 파일과 이번 수정이 있는 작업트리라 build_info에 `-dirty`가 기록되어 1개 게이트가 실패한다. 이것은 출처 검사의 정상 차단이다. 사용자 작업을 임의 커밋하거나 표식을 바꿔 통과시키지 않았다.

추가 운영 위험:

- gift ability seed는 주석의 “기존 행을 안 덮는다”와 달리 전체 delete/create이며 두 작업이 하나의 트랜잭션이 아니다. 중간 실패와 운영 저작 보존 정책을 정리해야 한다.
- `v2:build`는 실행 중 live canonical을 `canonical_hold`로 옮긴다. “최종 데이터 불변”은 “실행 중 서비스 무중단”과 다르다. 실패 복귀는 안내된 SQL을 사람이 실행하는 방식이다.
- CI는 원본/DB 기반 검증을 필수 게이트로 실행하지 않는다. 이 환경에서도 DB가 없을 때 40건이 skip되어 일반 테스트만 보면 문제를 놓칠 수 있었다.
- raw 재적재도 기존 스냅샷 삭제 후 스캔·적재하며 전체 트랜잭션이 없다. 입력 읽기 실패나 중간 오류에서 기존 스냅샷을 보존하는 절차가 필요하다.
- README의 초기 복원 절차에는 authored seed가 없고, 웹 절차에는 존재하지 않는 `npm run generate`가 남아 있다. 재현 가능한 실행 안내를 현행 명령으로 통일해야 한다.

## 4. 출시 전 작업 순서와 인수 기준

| 순서 | 담당 | 필요한 작업 | ops 인수 기준 |
| --- | --- | --- | --- |
| 1 | data | 원본 순서 보존, 승인된 override 복원, seed 원자성·정책 및 초기 적재 안내 | 깨끗한 검수 판본에서 빈 DB 복원 후 canonical 250개 전부 통과. 재적재 전후 저작 보존/값 재현 증거 |
| 2 | ops 조율 + design/data | 정보 MVP 문서·nav 정합화, 홈 표시 개수 통일 | 12개 정보 페이지 기준 일치, 실험 기능을 정식 기능으로 오인할 진입/설명 없음, 목록과 홈 숫자 일치 |
| 3 | design + data | 한·영 언어 태그, 필터 복원 범위, 결손·폴백 표시와 주요 탐색 QA | 목표 데스크톱/모바일 크기에서 검색→상세→팩→기프트 왕복 및 키보드/뒤로가기/0건 상태 검수 |
| 4 | data + ops | DB 접속·원본/저작/이미지 복원·릴리스 검증 및 복구 절차 | 다른 프로젝트 포트와 충돌 없는 기동, DB 검증 skip0, 빌드/승격 실패 시 서비스 복구 확인 |
| 5 | ops 최종 검수 | 배포 대상 및 운영 조건 결정 후 릴리스 판정 | 위 차단 항목 해소 증거가 있어야 공개 초기 버전 승인 |

기프트 강화 차이 강조, 이웃 기프트, 모든 구판 화면의 외형 재구현, 모든 표시 상수의 ETL 이관은 후속 개선이다.
잘못된 값·누락된 필수 설명·깨진 핵심 동선은 외형 완성 여부와 무관하게 차단한다.

## 5. 이번에 수행한 수정과 검수 환경

data에게 재요청하여 타입 오류를 4개 파일에서 최소 수정했다.
테스트 fixture의 배열 요소 존재를 확인하고, 기프트 능력 그룹의 첫 요소 가드를 추가했다.
타입 검사 설정·검증 기대값·게임 원본·제품 UI는 변경하지 않았다.

기본 5432 포트는 다른 프로젝트의 DB였고 기존 웹3000은 HTTP500을 반환했다.

- DB: `limbus-mvp-audit-20260908`, localhost 전용 포트 `15439`, PostgreSQL 17.
- 앱: 프로덕션 서버 `http://localhost:3100/ko`, 점검용 DB 연결.
