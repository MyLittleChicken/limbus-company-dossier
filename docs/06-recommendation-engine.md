# 추천 엔진 (Recommendation Engine)

> 상태: 초안 v0.1 / 최종 수정 2026-07-27
> 3단계(추천 엔진) 착수 전 문서. **무엇을 근거로 팩을 점수화하는가**를 정의한다.
> 설계의 뼈대는 이전 프로젝트(`limbus-mirror-tracker-v1`)의 `docs/03-data/master-book.md` 를 따르고,
> 데이터는 우리 1·2단계 산출물(52테이블 52,781행)을 그대로 쓴다.
> 이 문서의 수치는 2026-07-25 스냅샷 실측이다.

## 1. 이 단계의 범위

`00-product.md` 6절의 3단계 성공 기준은 **"임의의 런 상황을 입력했을 때 엔진이 팩 선택지를
점수화하고, 그 점수를 데이터상의 관계로 설명한다"** 이다.

| 구분 | 내용 |
| --- | --- |
| 범위 | 어휘 사전 · 조건 평가 · 덱 특성 · 기프트 한계 효용 · 팩 점수 · 근거 생성 |
| 범위 밖 | 런 상태 입력 흐름(4단계) · 플레이 로그 기반 가중치 학습(이후 버전) |

**엔진과 시스템을 구분한다**(`00-product.md` 5절). 엔진은 상황이 주어지면 점수와 근거를
내는 로직이고, 사용자가 플레이 중 자기 상황을 입력해 그것을 받는 흐름은 4단계다.

## 2. 지켜야 할 것

마스터북 §29의 12기준 중 이 단계에서 실제로 구속력을 갖는 것들이다.

1. **인격↔기프트를 직접 잇지 않는다.** 시너지는 저장된 사실이 아니라 상태에서 창발한다.
2. **분류 키워드와 발동 조건은 다른 것이다.** `화상 기프트`라는 분류와 `화상 스킬을 쓸 때`라는
   조건은 별개다.
3. **기프트를 하나의 점수로 다루지 않는다.** 효과 단위로 쪼개 각각 조건을 건다.
4. **편성과 출전을 구분한다.** 소집 12 · 온필드 7 · 백업 5.
5. **절대 점수가 아니라 한계 효용으로 판단한다.**
6. **설명은 평가가 남긴 근거에서 나온다.** 따로 지어내지 않는다.

## 3. 데이터 세 계층

| 계층 | 무엇 | 어디 |
| --- | --- | --- |
| 추출 | 원본 그대로. 해석 없음 | `gift_token` 2,204행 — 효과 55종 · 발동 150종 |
| 저작 | 토큰을 우리 어휘로 옮기는 규칙 | `lib/engine/vocab.ts` |
| 파생 | 덱 특성 · 활성도 · 점수 | 계산 결과. 저장하지 않는다 |

**토큰을 해석해서 적재하지 않는다.** `03-data-provenance.md` 6절이 `effects`/`triggers` 를
3단계에서 우리 기준으로 다시 정의하기로 했으므로, 파이프라인은 문자열만 담고
매핑은 엔진이 코드로 갖는다. 매핑이 바뀌어도 재적재가 필요 없고, 규칙이 리뷰 대상이 된다.

## 4. 어휘 사전

### 4.1 효과 55종

`Inflict {상태} Potency|Count` · `Gain {상태} Potency|Count` · `Deal {죄악} Damage` 는 규칙으로
잡고 나머지는 명시 표로 잡는다. 유형별 가중치는 `lib/engine/tuning.ts` 에 모았다.

`Other Uncommon Effects`(58회)는 **원본이 분류하지 않은 것**이지 우리가 분류하지 못한 것이
아니다. `UNCLASSIFIED` 로 낮은 가중치를 준다.

### 4.2 발동 150종

| 분류 | 토큰 수 | 판정 방식 |
| --- | ---: | --- |
| 무조건 (`Always`) | 1 | 항상 켜짐 |
| 스킬 사용 (`{상태·죄악·타입} Skill Used`) | 41 | 덱의 공급 인원으로 판정 |
| 소속 (`{소속} Identities`) | 28 | 편성·출전 인원 수 |
| 죄악 공명 (`{죄악} (Absolute) Resonance`) | 15 | 스킬 죄악 분포 |
| 상태·체력 (`Allies have …`) | 30 | 상태 공급으로 근사 |
| 기타 상황 (`Clash Win` 등) | 35 | 발동 빈도로 근사 |

**죄악은 여기서만 쓴다.** `{죄악} Skill Used` 와 `{죄악} Resonance` 는 인격 스킬의 죄악 분포로
판정하는 실제 게임 메커니즘이다. 기프트의 색 속성(`attributeType`)과는 무관하며 그것은
화면에도 엔진에도 쓰지 않는다([`backlog/03-gift-affinity.md`](backlog/03-gift-affinity.md)).

### 4.3 커버리지 게이트

**사전에 없는 토큰은 통과시키지 않는다.** 조용히 기본값으로 넘기면 점수가 그럴듯하게
나오면서 근거가 틀린다 — 1단계부터 피해 온 실패 방식이다(ADR-02 원칙 1).

실측 커버리지는 **효과 55/55 · 발동 150/150** 이다.

발동 토큰을 잇는 과정에서 **소속 이름 표기가 목록과 다른 것 10종**을 찾았다.
`Cinq Assoc.` 은 `Cinq Association` 의 줄임이고 `Yurodivy` 는 `Yurodiviye` 의 다른 표기다.
별칭표를 두어 이었으며 추정이 아니라 미분류 목록을 하나씩 확인한 결과다.

## 5. 조건 평가 — 세 값으로 답한다

한 조건에 참·거짓으로 답하지 않는다(마스터북 §11).

| 값 | 뜻 |
| --- | --- |
| `ratio` | 충족 정도. 3명 필요한데 2명이면 0.67 |
| `rate` | 발동 빈도. 전투 중 실제로 얼마나 켜지는가 |
| `evidence` | 무엇이 충족시켰는가. **추천 이유가 여기서 나온다** |

활성도는 `softStep(ratio) × rate` 다. `softStep` 은 미달을 제곱으로 깎아 **한 명 차이가
확실히 손해**가 되게 한다.

**소속 조건의 판정 범위가 기프트마다 다르다.** 기프트 9282 는 `편성 인원 기준`,
9283 은 `출격 인원 기준`이다. 원본 토큰에 그 구분이 없어 지금은 둘 중 큰 쪽을 쓴다.
정밀화는 설명문 파싱이 필요하며 후속이다.

## 6. 가치 모델

```
Score(state)        = Σ 보유 기프트 Σ 효과  가중치 × 대상계수 × 활성도
MarginalValue(gift) = Score(state ∪ {gift}) − Score(state)
```

**시너지를 엣지로 저장하지 않는다.** 공급 기프트를 넣으면 상태 공급이 올라 기존 수요
기프트의 활성도가 함께 오르고, 그 상승분이 한계 효용에 그대로 잡힌다. 시너지는 저장된
사실이 아니라 상태에서 창발하는 결과다.

이미 보유한 기프트의 한계 효용은 0이다. 중복 보유를 가정하지 않는다.

## 7. 팩 점수

```
PackScore = 즉시 강화 + 합성 진행 + 범용 + 한정 기회 + 미래 확장 − 중복
```

**전투 상성 항을 두지 않는다.** 마스터북 §18 의 `CombatMatchupValue` · `CombatRiskPenalty` 는
보스 내성 데이터를 전제하는데 우리는 인카운터의 등장 적만 담았고 내성은 담지 않았다.
없는 데이터로 항을 만들면 지어낸 값이 된다. 데이터가 생기면 더한다.

**층별로 가중치가 다르다.** 초반은 합성 재료와 미래 확장이, 후반은 즉시 강화가 무겁다.

### 7.1 등장성 — 모든 팩이 후보가 아니다

| 등급 | 대상 | 처리 |
| --- | --- | --- |
| `standard` | 나머지 전부 | 기본 후보 |
| `limited` | 발푸르기스의 밤 4종 | 이벤트 중에만 후보 |
| `hidden` | 뽕.황 1종 | **항상 제외** |

**뽕.황은 `category='extreme'` 인데 `extreme=false` 인 유일한 팩이다**(실측 1/117).
극히 낮은 확률로만 등장하는데 기프트 187종을 담고 있어, 두면 어떤 덱에서도 1위가 된다.
실제로 이 필터를 넣기 전 화진 덱 1위가 뽕.황(125.11)이었고 대조 덱에서도 1위였다 —
덱과 무관하게 이기므로 추천으로서 아무 말도 하지 않는 셈이었다.

**뺀 팩은 목록으로 보인다.** 조용히 버리면 왜 안 나오는지 알 수 없다(ADR-02 원칙 1).

## 8. 슬라이스와 증명

한 번에 전부 만들지 않고 층으로 나눠 각각을 증명한다(마스터북 §24).
`npm run engine:proof` 가 다섯 슬라이스를 순서대로 검사한다.

| 슬라이스 | 주장 | 증명 |
| --- | --- | --- |
| 0 어휘 | 원본 토큰을 빠짐없이 옮긴다 | 효과 55/55 · 발동 150/150 · 미분류 0 |
| 1 덱 특성 | 실제 덱을 바르게 읽는다 | 화진 덱의 상태·죄악·소속 공급을 실측과 대조 |
| 2 조건 | 조건이 덱에 반응한다 | 소속 기프트가 해당 덱에서만 값을 갖는다 |
| 3 한계 효용 | 덱 축의 기프트가 다른 축보다 높다 | 축별 평균 — 화상 1위 · 진동 3위 · 침잠 최하 |
| 4 팩 순위 | 덱이 바뀌면 순위가 바뀐다 | 화진 덱과 대조 덱의 순위·점수 비교 |

**축 단위로 봐야 한다.** 개별 기프트 한 종으로는 엔진이 덱을 읽는지 알 수 없다.
상위 개별 기프트는 조건 없는 범용(`선물` 7.52 · `포장용 상자` 3.36)이 차지하는데
그것은 어느 덱에서도 강하기 때문이며 잘못이 아니다. 판정은 키워드 축의 평균으로 한다.

| 축 | 화진 덱 평균 | |
| --- | ---: | --- |
| 화상 | 0.585 | 덱 축 |
| (없음) | 0.484 | 범용 |
| 진동 | 0.393 | 덱 축 |
| 호흡 | 0.273 | |
| … | | |
| 침잠 | 0.072 | 비축 — 화상의 1/8 |

대조 덱에서는 축 1위가 화상이 아니라 범용(`none` 0.499)으로 바뀐다.

**통과가 아니라 수치를 낸다.** "됐다"가 아니라 "몇 건 중 몇 건"이어야 다음 사람이 판단한다.

### 8.1 검증 대상 덱 — 화상·진동

첫 슬라이스의 대상은 **화상+진동 덱**이다. 통칭 화진 · 새벽엄지 · 엄지새벽이다.

| 인격 | 소속 |
| --- | --- |
| 새벽 사무소 해결사 (10216) · 새벽 사무소 해결사 (11009) · 새벽 사무소 대표 (11216) | Dawn Office 3 |
| 동부 엄지 카포IIII (10512) · 거미집 엄지 제자 (10716) · 거미집 엄지 아비 (10916) · 동부 엄지 솔다토II (11013) | The Thumb 4 |

이 덱을 고른 근거는 셋이다.

1. **7명이 온필드 정원과 정확히 맞는다.** 편성·출전 구분을 실제로 시험할 수 있다.
2. **두 소속 조건을 동시에 만족한다.** 기프트 9282 는 `새벽 사무소 3인 이상`,
   9283 은 `엄지 3인 이상`을 요구하며 이 덱이 둘 다 켠다.
3. **전원이 `wrath` 스킬을 갖는다.** 죄악 공명 조건을 시험할 수 있다.

실측 공급은 화상 7명 · 진동 6명 · `wrath` 7명이다.

### 8.2 대조군

같은 기프트가 **소속이 없는 덱에서는 값을 갖지 않아야 한다.** 기본 인격 7명을 대조군으로
두고 비교한다. 실측은 기프트 9282(날개 모양 양초)가 화진 1.656 대 대조 0.000 이다.

## 9. 화면

`/[locale]/recommend` 가 이 슬라이스를 보인다. **런 상태 입력은 없다** — 덱이 고정이고
층만 주소로 바꾼다. 그 흐름은 4단계의 몫이다(`07-recommendation-system.md`).

화면은 점수 하나가 아니라 항목별 분해와 근거를 함께 낸다. 뺀 팩도 이유와 함께 보인다.

## 10. 알려진 근사

지금 값이 정확하지 않은 지점을 적는다. 감추면 다음 사람이 정확한 줄 안다.

| 항목 | 지금 | 왜 |
| --- | --- | --- |
| 효과와 발동의 짝짓기 | **모든 발동을 AND 로 묶어 모든 효과에 건다** | 원본이 배열 두 개를 따로 줄 뿐 짝을 주지 않는다. 실제보다 보수적이다 |
| 효과의 크기 | 유형별 대표치 | 설명문에서 수치를 뽑는 일은 후속이다 |
| 소속 조건의 인원수 | 일괄 3인 | 토큰에 수가 없다. 설명문에만 있다 |
| 소속 조건의 판정 범위 | 편성·출전 중 큰 쪽 | 토큰에 구분이 없다 |
| 합성 진행 가치 | 0 | 후속 슬라이스 |
| 전투 상성 | 항 없음 | 보스 내성 데이터가 없다 |
| 상태 파생 관계 | 없음 | 상태 간 파생(진동→진동 폭발 등)은 저작 대상이며 후속이다 |
| **탄환 축** | **없음** | `StatusKey` 에 빠져 있다. **화진 덱 7명 중 3명이 탄환 공급자라 이번 검증에 직접 걸린다** ([`backlog/04`](backlog/04-ammo-mechanic.md)) |

## 12. 미결

- **소속 축이 정리되지 않았다.** 93종에 조직 아닌 것이 섞여 있고 조건에 쓰이는 것은 28종이다
  ([`backlog/01-identity-tags.md`](backlog/01-identity-tags.md)). 지금은 현재 기준 그대로 쓴다.
- **효과 값이 대표치다.** 같은 유형 기프트의 강약이 구분되지 않는다.
- **상태 축을 전수로 확인한 적이 없다.** `StatusKey` 여덟은 키워드 10종에서 출발해 혈사를 더한
  것이지 실측 토큰에서 뽑은 것이 아니다. 탄환이 그래서 빠졌고, 같은 누락이 더 있을 수 있다.
- **골든 시나리오가 다섯 슬라이스뿐이다.** 마스터북 §25 의 A~H 중 합성(E·F)과
  전투 상성(H)은 아직 없다.
