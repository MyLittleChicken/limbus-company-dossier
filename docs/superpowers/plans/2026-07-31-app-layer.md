# app 층과 검증 완성 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** **재생성해도 살아남는 층**을 만든다. 수동 보정(`field_override`)이 `canonical` 을 이기게 하고, 결손 1,549건을 작업 지시서(`build/gap-report.md`)로 뽑고, 트래커 골격을 세운다. 마스터북 완전 일치 쌍 7건을 전부 회귀 검사로 옮겨 검증을 닫는다.

**Architecture:** `app` 스키마가 처음 생긴다. `npm run v2:canonical` 의 `TRUNCATE` 범위에 **들어가지 않는다** — 스키마 경계가 곧 안전장치다(스펙 1절). 적재 순서는 `raw → canonical → override 덮기` 이며 override 는 마지막이다.

## Global Constraints

- **현행 파일 수정 금지** · **계획 1–7 산출물은 고치지 않는다**(스키마에는 더하기만)
- 예외 — `load-canonical.ts` 에 override 적용 단계를 **더한다**
- `TRUNCATE` 목록에 `app.*` 를 **절대 넣지 않는다**
- 신규 스키마는 `@@map`/`@map` snake_case
- 커밋 메시지 한국어

## Task 1: `app` 모델

```prisma
/// 사람이 게임에서 직접 확인해 채운 값. **canonical 을 덮어쓴다.**
///
/// 재적재가 이 테이블을 건드리지 않는다 — TRUNCATE 범위가 raw·canonical 이고
/// app 은 스키마가 달라 닿지 않는다(스펙 1절). 그것이 층을 가른 이유다.
model FieldOverride {
  entity    String
  entityId  String   @map("entity_id")
  field     String
  /// 로케일 무관이면 빈 문자열
  locale    String   @default("")
  /// 모양이 필드마다 달라 원문을 담는다
  value     Json
  /// 왜 이 값인가. "게임에서 직접 확인 2026-08-02"
  note      String
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)

  @@id([entity, entityId, field, locale])
  @@index([entity, field])
  @@map("field_override")
  @@schema("app")
}

/// 트래커 사용자.
model Account {
  id        String   @id
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)

  runs     Run[]
  settings Setting[]

  @@map("account")
  @@schema("app")
}

model Setting {
  accountId String @map("account_id")
  key       String
  value     Json

  account Account @relation(fields: [accountId], references: [id], onDelete: Cascade)

  @@id([accountId, key])
  @@map("setting")
  @@schema("app")
}

/// 거울 던전 한 판.
model Run {
  id         String     @id
  accountId  String     @map("account_id")
  difficulty Difficulty
  startedAt  DateTime   @map("started_at") @db.Timestamptz(3)
  endedAt    DateTime?  @map("ended_at") @db.Timestamptz(3)
  /// 도달 층
  floor      Int        @default(1)

  account Account   @relation(fields: [accountId], references: [id], onDelete: Cascade)
  floors  RunFloor[]
  gifts   RunGift[]

  @@index([accountId])
  @@map("run")
  @@schema("app")
}

/// 층마다 고른 테마 팩. **canonical 로 외래 키가 걸린다** — 같은 DB 라 가능하다.
model RunFloor {
  runId  String @map("run_id")
  floor  Int
  packId String @map("pack_id")

  run  Run  @relation(fields: [runId], references: [id], onDelete: Cascade)
  pack Pack @relation(fields: [packId], references: [id])

  @@id([runId, floor])
  @@index([packId])
  @@map("run_floor")
  @@schema("app")
}

/// 획득한 기프트. 강화 단계까지 담는다.
model RunGift {
  runId  String @map("run_id")
  giftId String @map("gift_id")
  level  Int    @default(0)

  run  Run  @relation(fields: [runId], references: [id], onDelete: Cascade)
  gift Gift @relation(fields: [giftId], references: [id])

  @@id([runId, giftId])
  @@index([giftId])
  @@map("run_gift")
  @@schema("app")
}
```

`Pack` 에 `runFloors RunFloor[]`, `Gift` 에 `runGifts RunGift[]` 를 더한다.

## Task 2: override 적용기

**Files:** `src/v2/canonical/override.ts` · `.test.ts`

**Interfaces:**
- `interface OverrideRow { entity; entityId; field; locale; value; note }`
- `function applyOverrides<T>(rows: T[], overrides: OverrideRow[], spec): T[]` — 순수
- 적재기가 `canonical` 을 채운 뒤 마지막에 부른다

### 규칙

```
canonical.status_text 에 ('FullCharon','ko') 행이 없다
app.field_override    에 status/FullCharon/name/ko = "완전한 카론"
  → status_text 에 행을 만든다 · field_source.rule = 'manual'

canonical.pack.textColor 가 NULL
app.field_override    에 pack/1001/textColor = "af241c"
  → 컬럼을 덮는다 · field_source.rule = 'manual'
```

**덮인 것은 `field_source` 에 `manual` 로 남는다.** 「이 값 왜 이렇지?」가 DB 안에서 답해져야 한다.

### 실제로 시험했다

결손 하나를 채우고 재적재해 살아남는지 확인했다.

```sql
INSERT INTO app.field_override VALUES ('status','FullCharon','name','ko','"완전한 카론"',…);
```

```
npm run v2:canonical
  → "수동 보정 1건을 덮는다"

canonical.status_text  FullCharon/ko  =  "완전한 카론"     ← 살아남았다
canonical.field_source FullCharon     rule = 'manual'      ← 근거가 남았다
app.field_override                    1건                  ← TRUNCATE 안 닿았다
canonical.field_gap    1,549 → 1,548                       ← 결손이 해소됐다
```

### 실행 중 잡은 것 — 결손이 해소되지 않았다

처음 구현은 보정을 덮기만 하고 `field_gap` 을 그대로 뒀다. **채웠는데 「없음」으로
계속 보고했고 `gap-report` 가 이미 채운 것을 다시 채우라고 시켰다.**

`Meta.resolve()` 를 더해 보정이 채운 결손을 지운다.

### 검사를 보정 인지형으로 만들었다

`status_text` 행 수와 한국어 결손 245는 보정이 늘면 달라진다. 실제 사용에서
보정이 쌓이므로 **보정 수를 되더해 비교**한다.

```
결손 1,548 + 보정 1 = 1,549      ← 원래 결손
한국어 결손 244 + 보정 1 = 245   ← 마스터북 실측
```
