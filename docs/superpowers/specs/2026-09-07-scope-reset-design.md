> 관련 [`00-product.md`](../../00-product.md) · [`05-ui-foundation.md`](../../05-ui-foundation.md) · [`backlog/13`](../../backlog/13-frontend-data-debt.md)

## 1. 왜

`00-product.md` 는 팩 추천을 차별점으로 두고 정보 페이지를 「위키와 같은 것」으로 낮췄다.
그 순서대로 넉 달을 갔고 지금 남은 것은 이렇다.

```
데이터     3스키마 114테이블 · 검증 222건 · 재현 바이트 일치         끝났다
정보 화면  16종 중 새 디자인 7 · 구 디자인 8 · 슬라이스 1          반이다
편성       /squad 편집 · 덱 코드 왕복 · 브라우저 저장               됐다
엔진       절 단위 켜짐 판정 + 값 모형(적합 2 · 등급 3 · 전용 0.25)  됐으나 미결 5건
트래커     07 §5.2 런 추적                                       없다
추천 화면  HWAJIN_DECK 고정 슬라이스                              제품 표면 아니다
```

**사람이 쓸 수 있는 것은 정보 화면뿐인데 그것이 반이다.** 추천 쪽은 표본 판정이
LLM 초안이고 사람 검토가 안 됐다(`2026-08-17-gift-score-design-결과.md`). 추천이
쓸 만해지는 시점을 지금 못 박을 수 없고, 그동안 정보 화면은 구판 8종을 안고 있다.

순서를 뒤집는다. **정보 사이트를 제품으로 두고 먼저 끝낸다.** 편성·추천·트래커는
그 뒤이며 추천과 트래커의 모양은 지금 정하지 않는다.

## 2. 결정

### 2.1 단계를 다시 매긴다

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| ① 정보 사이트 | 인격 · E.G.O · 기프트 · 팩 · 거울 던전 · 층의 조회·검색. **이것이 제품이다** | 이번 범위 |
| ② 덱 편성 | 서버 저장 덱. 익명 식별 기본 + Google OAuth 연동. 덱 코드 불러오기·복사 | 다음. 이 문서가 정하지 않는다 |
| ③ 덱 편성 추천 | RAG 와 유저 편성 데이터 기반 | **미정** |

| ⑤ 거울 던전 트래커 | 07 §5.2 런 추적 | **미정** |

옛 1~4단계와의 대응: 옛 1(데이터) 은 끝났고 ① 에 흡수된다. 옛 2(웹) 가 ① 이다.
옛 3(엔진) 이 ④, 옛 4(시스템) 가 ②+⑤ 로 갈라진다. ③ 은 새것이다.

### 2.2 ② 에 대해 지금 정해 두는 것 셋

이 문서는 ② 를 설계하지 않는다. 다만 ① 이 ② 의 자리를 막지 않도록 셋만 고정한다.

```
저장    서버. 브라우저 저장(lib/storage/decks)은 ② 에서 서버로 옮긴다
식별    익명 id(쿠키) 기본. Google OAuth 로그인은 유실 방지용이며
        익명 id → 계정 귀속(연동)이 반드시 있어야 한다. 로그인이 새 사용자를 만들지 않는다
입력    덱 코드 불러오기 · 복사. lib/deck-code 코덱을 그대로 쓴다.
        외부 커뮤니티 코드 호환은 기대이지 검증된 사실이 아니다 — ② 에서 실물로 확인한다
```

`00-product.md` 「하지 않을 것」의 「로그인 기능」은 지운다. ② 의 범위다.

### 2.3 ③④⑤ 는 「미정」이며 지우지 않는다

엔진 `lib/engine/v2` (테스트·골든 포함) · `scripts/rank/*` · `lib/storage` · `lib/deck-code` ·
`/squad` · `/recommend` 를 **삭제하지 않는다.** 미정은 미정이지 폐기가 아니다.
canonical 스키마가 바뀌면 이들의 테스트가 깨지고 그것이 곧 알림이다.

대신 **제품 표면에서 뺀다** (§3.3).

상세와 서로 링크하므로 짝으로 간다.

### 3.3 제품 표면 정리

```
nav      NAV_SECONDARY 에서 squad · recommend 제거 (glossary 는 이미 없다)
경로     /[locale]/squad → /[locale]/lab/squad
         /[locale]/recommend → /[locale]/lab/recommend
         /[locale]/glossary → /[locale]/lab/glossary

파일     rank.html (루트 untracked) 삭제. scripts/rank-page.ts 가 언제든 다시 만든다
```

`/lab` 을 두는 이유는 하나 — 엔진과 편성 코드가 **살아서 돌아가는 상태**로 남아 있어야
④⑤ 재개 때 대조할 것이 있다. 라우트를 지우면 코드는 남아도 실행 경로가 없어진다.

## 4. 소유

| | data surface (이 세션) | design surface |
| --- | --- | --- |
| 한다 | §3.2 D 항목 · §3.3 · §2.4 문서 | §3.1 화면 |
| 순서 | 기프트 상세가 기다리는 D0 · D2 · D11 · D3 · D14 · D4 (design 이 정한 차례: D2 레이아웃 차단 → D11 → D3 → D14 → D4) | 기프트 상세 → 팩 상세 → 홈 |
| 접점 | D 항목마다 질의 함수의 반환 타입을 먼저 보낸다. 화면은 그 타입으로 짠다 | 화면이 새로 필요한 값은 D 번호를 달아 돌려보낸다 |

같은 파일을 양쪽이 만지지 않는다. `lib/queries/**` · `src/**` · `prisma/**` 는 data,
`app/**` · `components/**` 는 design. `lib/ui-text.ts` · `lib/pack-label.ts` · `lib/pack-art.ts` 는
D 항목이 처리되는 시점에 data 가 지우거나 줄인다 — 그 전까지 design 이 읽기만 한다.
