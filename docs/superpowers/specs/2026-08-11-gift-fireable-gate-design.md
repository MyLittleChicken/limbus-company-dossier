# 기프트가 「켜질 수 없다」를 언제 말할 것인가 — 게이트

> 결정 2026-08-11 · 상태 제안

## 1. 왜

추천 엔진이 기프트를 너무 많이 죽인다. 화상·진동 골든 덱에서 451개 중 **178개가 「발동 불가」**다.

원인은 판정 규칙 한 줄이다.

```typescript
// lib/engine/v2/evaluate.ts
const fireable = !reasons.some(
  (r) => r.verdict === 'unsatisfied' && r.certainty === 'certain',
);
```

기프트에 붙은 제3자 트리거 태그를 **전부 충족해야 할 조건**으로 읽는다. 그런데 그 태그 목록은 조건만 담은 것이 아니다.

### 태그가 섞어 담는 것

전량 검수(456개, 2026-08-11)로 확인했다. 같은 목록에 세 가지가 섞여 있다.

```
발동 조건    「검계 소속 인격이 3인 이상일 때 발동」        기프트를 여는 문
적용 범위    「- 세븐 협회 소속 인격은 … 효과 적용」        누구에게 적용되는지
수혜 대상    검계 게이트 기프트의 attack_type/slash        효과가 무엇을 키우는지
```

9718 검계 기프트가 셋 중 둘을 한꺼번에 보여준다.

```
트리거 태그   association/BLADE_LINEAGE   ← 게이트 (검계 3인 이상)
              attack_type/slash           ← 수혜 대상 (참격이 강해진다)
```

지금 엔진은 **둘 다 「충족해야 할 조건」으로 읽는다.** 그래서 검계 3인이 있어도 참격이 없으면 죽인다 — 실제로는 켜지되 값이 낮을 뿐이다.

### 통째로 OR 로 바꾸면 더 나빠진다

「하나라도 충족하면 산다」로 뒤집으면 162개가 뒤집힌다. 그러나 표본 10건을 설명문과 대조하니 **OR 이 옳은 것 4, AND 가 옳은 것 5**였다.

```
OR 이 옳다    9043 사원증   「분노 완전 공명을 발동하였거나 충전 … 스킬을 사용할 경우」
              9018 장미 면류관  문단 1 이 무조건, 문단 2 만 공명 조건
AND 가 옳다   9005 상처붙이  「출혈 … 부여하는 스킬을 사용하여 적중 시」 — 출혈이 진짜 조건
              9048 커터 나이프  출혈이 조건, 색욕은 강화판
```

한 규칙으로 뒤집으면 고치는 것보다 망가뜨리는 것이 많다.

### 가르는 신호는 데이터에 있다

`min_count` 가 붙은 소속 참조 20짝을 전수로 봤다.

```
첫 문단이 「…N인 이상일 때 발동」   = 진짜 게이트          13건
  9212 피쿼드호3 · 9263·9264 약지2 · 9282 새벽3 · 9283 엄지3
  9717·9783·9785 흑운회3 · 9718·9719·9720·9784 검계3 · 9792 중지2
첫 문단이 다른 것                   = 문단 조건 또는 적용 범위   6건
  9220 · 9270 · 9280 · 9712 · 9778 · 9829
```

## 2. 목표 · 비목표

### 목표

「켜질 수 없다」를 **확신이 있을 때만** 말한다. 그 확신의 근거는 게이트다.

### 비목표

- **절(문단) 구조를 만들지 않는다.** 이 PR 은 규칙 하나다. 절 단위 판정은 기프트 능력 PR 의 몫이다.
- **저작 데이터를 만들지 않는다.**
- **점수 모형을 손대지 않는다.**
- 9052 · 9043 을 고치지 않는다 — 설명문을 읽어야만 알 수 있고, 그것이 기프트 능력 PR 이다.

## 3. 규칙

```
게이트가 있는 기프트    게이트만 발동을 막는다
                        나머지 참조는 수혜 대상이지 조건이 아니다

게이트가 없는 기프트    소속(association) · 유닛 키워드(unit_keyword) 는
                        적용 범위라 막지 않는다
                        나머지(축 · 공격타입 · 공명 · 자리)는 막는다
```

### 게이트의 정의

**설명문 첫 문단이 「…N인 이상일 때 발동」이고, 그 트리거에 `min_count` 가 있는 것.**

빌드가 판정해 `canonical.gift_trigger_param` 에 `kind='gate'` 로 굳힌다. 엔진은 구조만 읽는다 — 설명문을 다시 파싱하지 않는다(ADR-08 「규칙은 코드 · 사실은 데이터」).

기존 `min_count` · `denominator` · `slot` 을 뽑는 자리(`src/v2/canonical/gift-trigger-param.ts`)에 넣는다.

### 왜 소속은 안 막는가

전량 검수 표본 6/6 이 같은 구조였다.

```
9140 결의      참격 스킬 2개 이상 보유한 모든 아군이 …     ← 본 효과, 무조건
               시 협회 소속 인격이 …                       ← 소속 전용 추가
9194 케인 소드  참격 기본 공격 스킬로 합 승리 시 …
               - 세븐 협회 소속 인격은 … 효과 적용         ← 「- 」 하위 항목
```

소속 참조는 「누구에게 적용되는가」이지 「켜지는 조건」이 아니다. 게이트일 때만 예외다.

### 점수는 낮춘다

이 참조들을 `reasons` 에서 빼지 않는다. 근거 목록에 그대로 보이고 `satisfied / total` 에도 계속 센다.

```
검계 기프트를 검계 없는 편성에서 뽑으면
  켜진다      본 효과는 소속과 무관하게 돈다
  점수는 낮다  소속 전용 부분을 못 쓰니 적합도가 떨어진다
```

**「죽이지는 않되 값은 깎는다」**가 사실에 맞다. 지금은 죽여서 목록에서 아예 사라진다.

`Reason` 에 `blocking: boolean` 을 실어 근거 모달이 「이건 적용 범위라 켜짐을 막지 않는다」를 보일 수 있게 한다.

## 4. 실측

제안 규칙을 라이브 데이터로 돌렸다(`scripts/try-rule.ts`).

죽는 기프트   178 → 130      살아나는 것 48

## 5. 검증

### 단위

```
게이트가 있으면 게이트만 막는다 — 다른 참조가 미충족이어도 산다
게이트가 없으면 소속·유닛키워드는 안 막는다
게이트가 없으면 축·공격타입·공명·자리는 막는다
blocking 이 reasons 에 실린다
```

### 골든 (실 DB)

§4 의 10건을 그대로 박는다. **되돌려 확인한다** — 규칙을 되돌리면 「9140 이 산다」와 「9718 이 죽는다」가 실패해야 한다.

기존 골든의 실측 등급(A146 · B219 · C86)과 `발동 가능 273` 이 바뀐다. 실제 값으로 고치고 왜 바뀌었는지 주석을 남긴다.

### 적재 검증

```
gift_trigger_param 의 kind 어휘에 gate 가 있다
kind='gate' 인 짝은 반드시 같은 짝에 min_count 가 있다
gate 를 가진 기프트 수가 49 다
```

### 적용 범위 규칙이 남기는 과대 판정 4건

**받아들이고 머지한다**(2026-08-11 사용자 결정). 42덱 재검증으로 대안을 재 보니
적용 범위 규칙을 빼면 59기프트·1809덱-건을 잃고 **결의가 41/42 → 3/42 로 죽는다** —
이 PR 을 시작하게 한 바로 그 기프트다. 넷을 고치려고 쉰다섯을 망길 수 없다.

```
gift/9246 누군가 놓쳐버린 사원증   절 둘 다 소속 조건 (림버스 컴퍼니 · LCE)
gift/9778 통상 작전용 장비        절 둘 다 림버스 컴퍼니. 첫 절의 조건은 태그에 아예 없다
gift/9271 흑수환 - 묘            절 둘 다 묘. 각력【묘】는 흑수-묘 소속이 보유한 패시브다
gift/9843 경혈식 글레이브          절이 혈귀 조건 하나뿐. 게다가 크기가 (편성 수 - 2) 라
                                혈귀 0명이면 0을 지급한다 — 발동 여부와 크기가 따로다
```

넷 다 판별 기준이 「**무조건 절이 있는가**」 하나이고, 절을 나누면 자동으로 갈린다.
기프트 능력 PR 이 절 구조를 넣으면 넷이 동시에 사라진다.

### 검증 덱의 편성 모형 (2026-08-11 사용자 확정)

앞선 12덱 검증은 `roster` 6인 · `field` 같은 6인으로 짜서 세 가지가 망가져 있었다 —
`waiting` 분모가 공집합, 자리 7번 없음, 「N인 이상」의 분모가 6. 실제 거울 던전은
**편성 12인 · 출격 7인 · 대기 5인**이다. 42덱(축 8 · 소속 34)으로 다시 돌린 결과가
이 문서의 근거다. 엔진의 `roster`/`field`/`waiting` 은 처음부터 옳았다.

전량 검수의 나머지 결과(86건 중 71건을 담는 설계, 15건 결손)는 기프트 능력 스펙이 받는다.

## 7. 안 하는 것

- `axis` · `attack_type` · `resonance` · `deployment` 의 판정을 바꾸지 않는다. 9005 · 9023 · 9048 · 9041 은 여전히 죽는다 — 그것이 옳다.

### 언제 걷어내는가

**이 규칙은 임시방편이다.** 절 구조가 들어오면 조건이 어느 절에 붙는지 데이터가 직접 말하므로 「첫 문단이면 게이트」라는 근사가 필요 없어진다.

기프트 능력 PR 이 절 구조를 넣을 때 함께 지운다.

```
canonical.gift_trigger_param 의 kind='gate' 49행
lib/engine/v2/evaluate.ts 의 gateKeysOf · hasGate · SCOPE_KINDS
src/v2/verify-canonical.ts 의 게이트 검사 둘
lib/engine/v2/gate-golden.test.ts
```

`Reason.blocking` 은 남긴다 — 절 구조에서도 「이 근거가 발동을 막는가」는 여전히 필요하고, 그때는 절이 그 값을 정한다.

**두 진실을 만들지 마라.** 절 구조가 들어온 기프트는 `kind='gate'` 를 더 이상 보지 않아야 한다.
- `evaluability` 를 손대지 않는다. 이 필드가 「전투 중 조건은 안 죽인다」를 떠받치고 있고(46종 · 282 기프트), 근거가 약하다는 것은 알지만 대체는 절 구조가 들어올 때다.
- 저작 데이터를 만들지 않는다.
