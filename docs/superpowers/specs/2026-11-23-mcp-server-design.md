## 1. 무엇이고 왜

사이트 사용자가 자기 AI 에이전트(Claude · ChatGPT 등)에 우리 MCP 주소를 붙이면, 에이전트가
도감 DB 를 **도구 호출로** 읽는다. 사용자는 「이 기프트 뭐 해?」「화상 덱에 3층 팩 뭐 골라?」
「내 보유로 짤 수 있는 진동 덱은?」을 에이전트에게 묻고, 에이전트는 우리 데이터로 답한다.

두 층이다.

```
조회 층     DB 의 모든 정보를 세부까지 · 서로 엮인 채로. 로그인 없음
개인화 층   로그인한 사용자의 보유 목록(A) · 저장한 편성(B) 을 읽어 추천 재료로. 로그인 필요
```

런 기록(C) 기반 개인화는 트래커(⑤) 를 만들 때 함께 정한다. 이 문서의 범위가 아니다.

**추천은 혼합 방식이다(사용자 결정).** 서버가 완성된 추천을 내지 않는다. 엔진이 잘하는
「틀리지 않는 판정」을 도구로 열고, 조합·설명은 에이전트가 한다.

```
엔진이 단정하는 것    기프트가 이 편성에서 켜지나 + 근거 · 편성의 축 · 팩 기프트 풀
엔진이 참고로 주는 것  팩 점수 · 순위 — 저울추(적합 2 · 등급 3 · 전용 0.25)가 LLM 초안
                     표본에서 나왔고 사람 검토 전이다. 응답에 그 사실을 박는다
에이전트가 하는 것    보유 목록에서 덱 후보를 조립 · 판정 도구로 확인 · 사용자에게 설명
```

덱 카탈로그(limbus.ing 식 등록 덱 순위)는 만들지 않는다. 필요해지면 그때 도구 하나를 더한다.

## 2. 목표 · 비목표 · 반목표

**목표**

- 사이트가 보여 주는 정보 전부를 도구로 꺼낼 수 있다: 인격 · E.G.O · 기프트 · 팩 · 층별 팩 ·
  거울 던전(은총·구성) · 상태/키워드 · 수감자 · 죄악 · 데이터 기준 버전.
- 응답이 서로 엮인다: 기프트 상세가 등장 팩 id 를, 팩 상세가 기프트 id 를, 인격 상세가 키워드
  id 를 준다. 에이전트가 id 로 다음 도구를 부를 수 있다.
- 엔진 판정을 로그인 없이 쓴다: 덱은 덱 코드 또는 인격 id 목록으로 직접 넘긴다.
- 로그인하면 같은 도구가 「내 덱 id」를 받고, 목록 도구가 「보유한 것만」으로 거를 수 있다.

**비목표 (이번에 안 한다)**

- 쓰기 도구. 덱 저장·보유 등록은 사이트에서 한다. MCP 는 읽기 전용이다.
- 서버 측 덱 추천 · 덱 카탈로그.
- 런 기록(C) · 트래커.
- 공개 REST API. 필요하면 같은 질의 층 위에 나중에 얹는다.
- 별도 MCP 서비스. 사이트 안에 둔다(§4).

**반목표 (돌아가도 실패인 것)**

- 에이전트가 초안 점수를 사실처럼 말한다 → 점수 응답에 `provisional` 표시와 이유를 박는다.
- 결손을 빈 값으로 감춘다 → 화면처럼 결손은 결손이라고 응답에 적는다(폴백 로케일 포함).
- 이미지·원본 파일을 재배포한다 → 텍스트 사실과 사이트 링크만 준다(§5).
- 사이트와 MCP 가 다른 답을 낸다 → 둘이 같은 질의 함수를 쓴다.

**성공의 모습** — 사용자가 Claude 에 사이트의 MCP 주소를 붙이고 「내 화상 덱에서 〈기프트〉
켜져?」라고 물으면, 에이전트가 `get_my_deck` → `check_gifts` 를 불러 근거와 함께 맞게 답한다.

## 3. 선행 조건 — 공개 전에 정해야 하는 것

```
배포처      미정(adr/05 3.5). 공개 MCP 는 공개 HTTPS 주소가 있어야 한다
IP 조건     01-data-source 7절 — 2차 창작 가이드라인 원문 미확보. 「DB 전체를 내려준다」는
            사이트보다 재배포 성격이 강하다. 공개 전에 원문 확인
계정(②)     개인화 층만 막는다. 조회 층은 ② 없이 나간다
```

로컬 개발과 1 덩어리 구현은 선행 조건 없이 시작한다. **공개**만 막힌다.

## 4. 짜임 — 사이트 안의 `/mcp` (사용자 결정)

검토한 세 갈래:

| | 방식 | 판단 |
| --- | --- | --- |
| **A** | Next.js 앱에 `/mcp` 경로. 질의 함수·엔진을 직접 호출 | **채택.** 한 제품 · 한 로그인 · 한 배포. 초기 규모에 맞다 |
| B | 별도 Node MCP 서비스가 같은 `lib` 를 씀 | 부하 분리 이점이 사용자 0 인 지금 없다. 배포·로그인이 둘 |
| C | 공개 REST API 를 먼저, MCP 는 그 위 | 표면이 둘. 요청은 에이전트 도구이지 API 가 아니다 |

나중에 B 로 떼기 쉽게, 도구 정의는 Next.js 에 기대지 않는 모듈에 둔다.

```
lib/mcp/
  server.ts        McpServer 생성 · 도구 등록. 프레임워크 무관
  tools/*.ts       도구별 입력 스키마(zod) · 핸들러 · 응답 변환
  shape.ts         질의 함수 결과 → 에이전트용 모양 (§6.3)
app/mcp/route.ts   Streamable HTTP 받기. 인증 정보를 server 에 넘긴다
```

- SDK: `@modelcontextprotocol/sdk` (TypeScript 공식). 전송은 Streamable HTTP, **무상태**
  (요청마다 서버 생성 또는 세션 없이 처리). 서버리스 배포처를 배제하지 않기 위해서다.
- `/mcp` 는 `[locale]` 밖이다. 로케일은 도구 인자다.
- 질의는 `lib/queries/canonical/*` 와 `lib/engine/v2` 만 쓴다. `raw` 스키마를 읽지 않는다.

## 5. 지켜야 할 것

- **canonical 읽기 전용.** MCP 경로에서 쓰기 트랜잭션이 없다(개인화의 사용자 데이터도 읽기만).
- **이미지 없음.** 응답에 이미지 URL · 스프라이트 경로를 넣지 않는다. 대신 사이트 상세 페이지
  절대 URL(`siteUrl`)을 준다. 이미지 사용 조건이 확인되면 다시 본다.
- **출처·면책.** 서버 `instructions` 와 `get_build_info` 응답에 데이터 출처 · 2차 창작 표시 ·
  기준 스냅샷을 담는다(01-data-source 7절 「출처 크레딧과 면책 고지」).
- **데이터 기준 표시.** 모든 응답 머리에 `snapshotId` 하나. 에이전트가 「언제 데이터인지」
  말할 수 있게.
- **로케일.** `ko` · `en`. 기본 `ko`. 없는 문구는 다른 로케일로 폴백하고 `fellBack: true`.
  (화면의 `nameOf` · `textOf` 규칙 그대로.)
- **호출 제한.** 익명은 IP 당, 로그인은 계정 당. 수치는 빌더 몫(§9).

## 6. 도구

### 6.1 조회 층 (로그인 없음)

| 도구 | 감싸는 함수 | 메모 |
| --- | --- | --- |
| `search` | `searchAll` | 종류 섞인 결과. 한글 초성 검색 그대로 |
| `list_identities` · `get_identity` | `listIdentitiesFull` · `getIdentity` | 필터: 수감자 · 성급 · 죄악 · 키워드 · 시즌 |
| `list_egos` · `get_ego` | `listEgosFull` · `getEgo` | 필터: 수감자 · 등급 · 죄악 |
| `list_gifts` · `get_gift` | `listGifts` · `getGift` | 상세는 강화 0/+/++ · 등장 팩 · 저주/축복 짝 |
| `list_packs` · `get_pack` | `listPacks` · `getPack` | 상세는 기프트 풀 · 등장 층 |
| `list_floor_packs` | `listFloorPacks` | 층 · 난이도 |
| `get_dungeon` | `getDungeon` | 층 구조 · 은총 |
| `list_statuses` | `listStatuses` | 상태/키워드 설명 |
| `list_vocab` | `listSinners` · `listKeywords` · `listSins` · `listAxisLabels` | id ↔ 이름 사전 한 번에 |
| `get_build_info` | `getBuildInfo` | 스냅샷 · 출처 · 면책 |

목록 도구는 **요약**(id · 이름 · 핵심 메타 몇 개 + `siteUrl`)과 커서 페이지를 준다. 세부는
`get_*` 가 준다. 에이전트의 맥락 창을 목록이 다 먹지 않게 하기 위해서다.

### 6.2 엔진 판정 (로그인 없음 · 덱을 직접 넘김)

덱 입력은 셋 중 하나:

```
deckCode      게임 덱 코드 문자열 — lib/deck-code 로 푼다
identityIds   편성 인격 id 목록 (최대 12) + 선택 deployedIds (최대 7)
deckId        내 저장 덱 id — 로그인 시에만 (§6.4)
```

| 도구 | 감싸는 것 | 단정/참고 |
| --- | --- | --- |
| `decode_deck_code` | `lib/deck-code` | 단정. 출전 인원은 코드에 없다고 응답에 적는다 |
| `analyze_deck` | `listSquadAxes` 계열 · `Profile` | 단정. 편성이 공급하는 키워드 · 죄악 · 메카닉 축 |
| `check_gifts` | `evaluateGifts` · `chain` | 단정. 기프트 id 들에 대해 켜짐 여부 + 절 단위 근거. 보유 기프트(`heldGiftIds`)를 받으면 연쇄까지 |
| `score_packs` | `recommendForDeck` 의 점수 부분 | **참고.** 층 · 난이도 · 보유 기프트를 받아 팩별 점수와 근거. `provisional: true` 와 이유 |

**출격은 덱 코드의 편성 순서에 들어 있다(게임 실물 대조 2026-11-23).** 사용자가 준 편성 #24
의 덱 코드와 편성창 캡처를 맞대 봤다. 카드에 찍힌 숫자가 덱 코드 `FIELD.order` 와 12칸 모두
같았고, **순서 1–7 이 `SELECTED`(출격) · 8–12 가 `BACKUP`(대기)** 였다. 편성창 머리의
「대기 인원 편성 5/5」가 대기 상한 5 를 보여 준다. 덱 코드의 나머지 빈 비트(블록마다 1 · 꼬리 8)는
전부 0 이라 출격을 따로 담는 칸은 없다 — 순서 자체가 출격을 말한다.

```
규칙   순서 1..min(7, 편성 인원) = 출격,  나머지 = 대기 (최대 5)
근거   표본 1개(편성 #24, 12인) + 편성창의 대기 상한 표시
미확인 편성이 12 미만일 때(예: 9인)도 같은지 — 상한 규칙상 같을 것이나 실물 미대조
```

판정은 편성 12 · 출격 7 · 대기 5 를 따로 센다(기프트 설명문이 셋을 구분한다). 그래서

```
deckCode      순서에서 출격·대기를 바로 낸다 — 정확
deckId        저장 덱의 순서에서 같은 규칙으로 — 정확
identityIds   목록 차례를 편성 순서로 읽는다. 앞 7 이 출격. 도구 설명에 그렇게 적는다
deployedIds   주어지면 그것을 우선한다 (게임과 다른 「만약」을 물을 때)
```

부수 사실: 대기 카드에 「시작 정신력 +15 · +20 · +30」이 붙는다. 진입 시점에 정해지는
값이지만 지금 판정 모형에 없다 — 이 문서 범위 밖으로 적어만 둔다.

`lib/deck-code/codec.ts` 의 `deckFromCode` 는 지금 「덱 코드는 출전을 담지 않는다」며
`deployed` 를 비운다. 이 발견으로 틀린 주석이 됐다 — 1 덩어리에서 순서로 채우게 고친다.
`StoredDeck.deployed` 는 순서에서 파생되므로 ② 에서 저장 칸으로 둘지 다시 본다.

**축은 두 층을 섞지 않는다.** 「인격 취급」(`identity_axis` 의 tag · `identity_keyword`) 과
「스킬 취급」(`coin_token`) 은 다른 판정이고 어긋나는 짝이 21개다(예: 10104 는 진동 스킬을 쓰지만
진동 인격이 아니다). `analyze_deck` 은 두 층을 따로 세어 주고, `list_identities` 의 키워드 필터는
층을 인자(`axisLayer: 'tag' | 'skill'`, 기본 `tag`)로 받으며, 응답의 인격 요약도 두 층을 따로
적는다. `check_gifts` 는 조건이 말하는 층을 엔진 그대로 쓴다 — 도구끼리 모순이 안 나는 길이다.

**켜짐은 세 값이다.** 엔진의 `fireable` 은 「못 켠다는 근거가 없다」라서 런타임 조건·판정 불가도
`true` 다. boolean 하나로 내리면 반목표를 어긴다. 응답은

```
on        켜짐이 확정 (모든 조건 certain · satisfied)
possible  못 켠다는 근거는 없으나 런타임 조건 · 판정 불가(unknown) 가 남음
off       못 켠다 (근거 절 명시)
```

에 더해 엔진 필드(`grade` · `certain` · `decidable` · 절별 근거)를 그대로 싣는다. 판정 행이 없는
기프트는 `possible` + 「판정 데이터 없음」이다(화면처럼 `true` 로 두지 않는다).
**판정은 강화 0단계 절만이다**(`loadEngineData` 가 level 0 만 싣는다) — 응답에 적는다. 단계별
판정은 범위 밖이다.

**E.G.O 장착을 엔진에 넘긴다.** 덱 코드 · 저장 덱에 든 E.G.O 를 `egoIds` 로 넣어
`ego_equipped` 게이트가 셈에 들어가게 한다. `identityIds` 입력에도 선택 `egoIds` 를 둔다.
`/recommend` 화면은 언제나 빈 배열이라 같은 덱에서 숫자가 갈릴 수 있으나, 그 화면은 제품 표면이
아닌 실험 슬라이스(`/lab` 예정)이므로 MCP 쪽이 정답 쪽이다. 화면을 맞추는 것은 ④ 재개 때.

`heldGiftIds` 는 사용자가 대화에서 말한 런 중 보유 기프트를 에이전트가 넘기는 것이다. 저장하지
않는다 — 그것이 런 기록(C)이 되는 순간 트래커 범위다.

`recommendForDeck` 은 지금 화면용으로 `HWAJIN_DECK` 기본값과 UI 모양을 섞어 갖는다. 엔진
부분을 질의 함수에서 떼어 MCP 와 화면이 같이 부르게 하는 것은 빌더 몫이다. 단 **화면 결과가
바뀌면 안 된다** — 기존 골든(`rank-golden` 등)이 지킨다.

### 6.3 응답 모양

질의 함수는 화면용이라 `href` · `icon` · 스프라이트 같은 것을 섞어 준다. `shape.ts` 가 바꾼다.

```
뺀다     icon · sprite · 아트 합성값 · 화면 전용 클래스
바꾼다   href → siteUrl (절대 URL)
남긴다   id · 이름 · 설명 · 수치 · 연결 id · fellBack · 결손 표기
더한다   snapshotId (응답 머리)
```

출력은 MCP `structuredContent`(JSON) 와 사람이 읽을 `text` 요약을 함께 준다. 도구마다
`outputSchema` 를 선언한다.

### 6.4 개인화 층 (로그인 필요 · ② 위에 선다)

| 도구 | 내용 |
| --- | --- |
| `get_my_roster` | 보유 인격 · E.G.O (+ ② 가 레벨을 담으면 레벨) |
| `list_my_decks` · `get_my_deck` | 저장한 편성. 슬롯 · 편성 순서 · 출전 |
| 기존 도구 확장 | `list_identities` · `list_egos` 에 `ownedOnly`. 엔진 도구에 `deckId` |

에이전트가 「내 보유로 진동 덱」을 짜는 흐름:
`get_my_roster` → `list_identities(keyword=진동, ownedOnly)` → 후보 편성 → `analyze_deck` ·
`check_gifts` 로 확인 → `score_packs` 를 참고값으로.

로그인 없이 개인화 도구를 부르면 「사이트에서 Google 계정을 연동하고 다시 연결하라」는
안내를 오류 내용으로 준다.

## 7. 인증

- 조회·엔진 도구: 인증 없음.
- 개인화 도구: MCP 인가 규격(OAuth 2.1)으로. 우리 사이트가 인가 서버를 겸한다. 에이전트를
  연결하면 사이트의 Google 로그인 → 동의 화면 → 토큰.
- **익명 id 사용자는 개인화 MCP 를 못 쓴다.** 익명 id 는 브라우저 쿠키라 에이전트에 없다.
  Google 연동(② 의 「익명 → 계정 귀속」)을 한 계정만 쓴다.
- 인증 라이브러리는 ② 설계에서 고른다. 조건 하나를 여기서 박는다: **MCP 클라이언트용 OAuth
  발급(동적 클라이언트 등록 포함)을 지원할 것**(예: better-auth MCP 플러그인). 직접 OAuth
  서버를 짜지 않는다.
- 토큰 범위는 읽기 하나(`dossier:read`). 쓰기 도구가 없으므로.

## 9. 빌더에게 남기는 것

- 도구 이름·인자 이름의 세부 철자, zod 스키마.

  둘지).
