# 데이터 출처 분석 (Data Provenance)

> 상태: 초안 v0.1 / 최종 수정 2026-07-25
> `data/`에 수집한 스냅샷이 **어떤 경로로 만들어진 데이터인지** 분석하고, 계층별 신뢰도를 판단한다.
> 수집 대상과 사용 조건은 `01-data-source.md`에 있다.

## 1. 결론

수집한 데이터에는 성격이 다른 두 층이 섞여 있다.

| 층 | 생성 경로 | 비중 |
| --- | --- | --- |
| **추출층** | 게임 클라이언트에서 추출한 정적 데이터 | 대부분 |
| **저작층** | 저장소 관리자가 손으로 작성한 분류·서술 | 일부 필드 |

두 층은 **파일 단위가 아니라 필드 단위로 섞여 있다.** 같은 파일 안에서 추출된 값과 사람이 쓴 값이 나란히 있다.
따라서 "이 저장소는 신뢰할 수 있는가"가 아니라 "이 **필드**는 어느 층인가"로 판단해야 한다.

## 2. 추출층 — 근거

### 2.1 한국어 로컬라이제이션 저장소

게임 클라이언트의 로컬라이즈 리소스를 그대로 덤프한 것이다.

- 파일명이 게임 내부 리소스 이름과 일치한다: `Personalities.json`, `Skills_personality-01.json`, `Bufs.json`, `BattleKeywords.json`, `MirrorDungeonTheme-1.json`.
- 구조가 Unity 텍스트 애셋 형식이다. 최상위가 `dataList` 하나뿐이다.
- 내부 토큰이 정제되지 않은 채 남아 있다: `[Combustion]`, `<color=#d40000><s>…</s></color>`, `<noparse>`.
  가공된 데이터라면 남아 있을 이유가 없는 값이다.
- 언어별로 브랜치가 나뉜다. 같은 파일을 언어만 바꿔 덤프한 구조다.

### 2.2 구조 데이터 저장소

게임의 정적 데이터 테이블에서 유래한 형태다.

- 식별자가 게임 내부 id 체계를 그대로 쓴다(인격 `10101`, E.G.O `20101`, 기프트 `9001`).
- 값의 형태가 표시용이 아니라 **엔진 입력용**이다. 패시브가 `condition.requirement` 형태의 구조화된 조건으로 들어 있고,
  스킬 수치가 uptie 1→4 **델타**로 저장되어 있다. 사람이 표를 옮겨 적었다면 나오지 않는 구조다.
- 애셋 파일명이 내부 키가 아니라 게임의 `srcPath` 기준이다.
- 저장소 README에 방법론 언급이 없고 `meta.json`에 동기화 시각만 있다. 자동 파이프라인으로 갱신된다는 뜻이다.
- 저장소에 포함된 유일한 스크립트가 PNG를 WebP로 변환하는 것뿐이다. **PNG 덤프를 외부에서 받아 변환만 한다**는 의미다.

### 2.3 추출층임을 뒷받침하는 다른 증거

- `monthofjune/limbus_data`의 `meta.json`에 `"source": "dumped"` 라고 **명시되어 있다.**
- 2023년 시점의 게임 원본 덤프가 공개 저장소로 존재한다(`PGGB/limbus-company-data`, `Rcrwrate/Limbus-Company-Work-Dataset`).
  경로가 `Assets/Resources_moved/StaticData/` 와 `Assets/Resources_moved/Localize/` 로, 게임 클라이언트의 리소스 구조를 그대로 담고 있다.
  현행 데이터가 아니므로 로컬에는 보관하지 않는다. 재확인이 필요하면 `data/manifest.json`에 기록된 커밋 해시로 다시 받는다.
- 클라이언트를 frida-il2cpp로 덤프한 코드 저장소(`yuvlian/LimbusDumpCS`)가 존재한다.
  게임 바이너리에서 클래스 정의를 추출하는 작업이 커뮤니티에서 이루어지고 있다는 뜻이다.

## 3. 저작층 — 근거

아래 값들은 게임에 존재하지 않는다. 저장소 관리자가 판단해서 붙인 것이다.

| 위치 | 내용 | 저작층으로 판단한 근거 |
| --- | --- | --- |
| 인격 상세의 `notes` | 영어 산문 조언 | "useful for E.G.O spamming in MD" 같은 **평가 문장**. 게임 텍스트가 아니다 |
| `md/universal_gifts.json` | 기프트 분류 체계 | "Power & Clashing" → General / Slash / Pierce 식의 **편집 목차**. 게임에 없는 분류다 |
| `gifts.json`의 `effects` · `triggers` | 통제 어휘 55종 · 150종 | 456종 중 451종에 부여. **"Other Uncommon Effects"** 라는 catch-all 항목이 있다는 것 자체가 사람의 분류라는 증거다 |
| `alt_names.json` | 커뮤니티 별칭 | `Base`, `BL`, `DongBaek` 등 영어권 약칭. 게임 데이터가 아니다 |

`md/universal_gifts.json`은 456종 중 일부만 다룬다. **전수가 아니라 부분집합**이다.

## 4. 계층별 신뢰도

| 항목 | 추출층 | 저작층 |
| --- | --- | --- |
| 게임과의 일치 | 1:1 | 작성자의 해석 |
| 커버리지 | 전수 | 부분 |
| 패치 반영 | 자동 동기화 | 사람이 갱신해야 함 |
| 검증 가능성 | 게임과 대조 가능 | 대조 대상이 없음 |
| 오류 유형 | 파싱·매핑 실수 | 오분류, 낡은 판단, 누락 |

**이 프로젝트에서의 취급**

- 정보 제공(1~2단계)은 **추출층만으로 구성한다.** 저작층 없이도 필요한 필드가 모두 나온다.
- 저작층은 참고만 하고 그대로 옮기지 않는다. 특히 `effects`/`triggers`는 추천 엔진(3단계)에서 우리 기준으로 다시 정의한다.
- 저작층 값을 화면에 노출할 경우 출처가 게임이 아님을 표시해야 한다.

## 5. 이번 스냅샷 검증 결과

2026-07-25 수집분(19개 출처, 20,714 파일)에 대한 검증 결과는 `04-data-inventory.md`에 있다. 요지만 옮기면 다음과 같다.

| 검사 | 결과 |
| --- | --- |
| JSON 파싱 | 9,846개 전부 성공. BOM 포함 29개는 제거 후 파싱 |
| 인격 · E.G.O · 테마 팩 | 5개 독립 출처가 각각 184 / 110 / 117로 완전 일치 |
| 거울 던전 기프트 | 456. 다른 출처(441)의 완전 상위집합 |
| 기프트 ↔ 팩 교차 참조 | 양방향 불일치 0 |
| 애셋 | 인격 184/184, E.G.O 110/110, 기프트 456/456, 테마 팩 117/117 |

**검증의 한계.** 위 검사는 *내부 정합성*과 *출처 간 일치*를 본 것이다.
게임 클라이언트와 직접 대조하지 않았으므로, **추출층의 정확성은 상류 저장소를 신뢰한 결과다.**
여러 출처가 서로 독립적으로 같은 값을 내놓는다는 사실은 신뢰도를 높이지만, 모두 같은 게임에서 추출된 이상
공통된 추출 오류가 있다면 이 방법으로는 드러나지 않는다.

## 6. 위험

1. **두 출처 모두 개인 운영이고 라이선스가 없다.** 저장소가 내려가면 대체 경로가 필요하다.
2. **수량은 계속 변한다.** 이전 프로젝트가 2026-07-21에 기록한 인격 수는 183이었고, 이번 수집에서는 184다.
   나흘 만에 바뀌었다. 문서에 적은 수치는 항상 스냅샷 시점과 함께 읽어야 한다.
3. **저작층을 추출층으로 오인하면 틀린 정보를 사실처럼 노출하게 된다.** 3절의 구분을 코드 주석이 아니라 데이터 구조에 반영해야 한다.
4. 원본 게임 데이터와의 대조 수단이 현재 없다.

## 7. 미결

- 상류 저장소가 중단될 경우의 대체 경로.
- 추출층을 게임과 직접 대조할 수단을 확보할지 여부.
- 저작층 필드를 아예 배제할지, 출처 표시와 함께 사용할지.
