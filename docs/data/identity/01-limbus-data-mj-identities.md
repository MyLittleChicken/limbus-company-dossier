## 파일 정체

인격 184종의 요약 레코드. ADR-04가 인격의 정본으로 이 출처를 고른 이유는 `limbus-assets` 의
인격 필드를 전부 덮으면서 **한국어를 인라인으로 갖기** 때문이다(`nameKo`/`titleKo`).

다만 이 파일은 **요약본**이다. 스탯의 원본은 `identities_detail.json`(회차 2)이고,
태그·상태의 어휘 정본은 `limbus-assets`(회차 6)다.

**23개 키 중 실제로 적재되는 것은 8개.** 나머지 15개가 왜 안 쓰이는지가 이 회차의 절반이다.

### `title` / `titleKo` — 인격명

| | |
| --- | --- |
| 타입·실측 | `title` 184/184 · `titleKo` 183/184 · 마크업 포함 0건 · **title 중복 27종** |
| 의미 | 화면에 뜨는 인격 이름 |
| 변환 | `stripMarkup(titleKo ?? title)` → ko, `stripMarkup(title)` → en |
| 적재 | `identity_text.name` (ko·en 2행) |
| 화면 | 목록 카드 제목 · 상세 헤더 · 검색 대상 |
| 함정 | 아래 셋 |

**함정 1 — 인격명은 유일하지 않다**

```
LCB Sinner              12건    Blade Lineage Salsu       5건
Kurokumo Clan Wakashu    4건    W Corp. L3 Cleanup Agent  3건
… 총 27종이 중복
```

**수감자명과 짝지어야 구별된다.** 상세 화면이 부제에 수감자명을 넣는 이유다.

**함정 2 — `titleKo` 결손 1건은 결손이 아니다**

```
11215  title = "LCE E.G.O:: AEDD"   titleKo 없음
```

한국판 게임도 같은 표기를 쓴다. `titleKo ?? title` 폴백이 옳게 동작한다.
다만 반대 방향(en 결손 시 ko 폴백)은 없다 — `docs/backlog/02-locale-fallback.md`.

**함정 3 — `stripMarkup` 은 여기서 no-op 이다**

이 파일의 `title` 184건에는 마크업이 **하나도 없다.** 그래도 통과시키는 것은
같은 처리 계보를 유지하기 위해서다. 다른 출처에는 실제로 있다.

```
"<color=#d40000><s>Great Sister</s></color>"   →  Great Sister      (지운다)
"<라만차랜드>소속, <혈귀>(상위 권속)인 아군"        →  그대로            (남긴다)
```

`stripMarkup`(`src/text.ts:202`)은 Unity 리치텍스트 33종만 지우고 게임이 표기로 쓰는
꺾쇠는 보존한다. 실측 리터럴은 `<혈귀>` 29건 · `<라만차랜드>` 16건 · `<피주머니>` 5건 등이다.

### `updatedDate` — 출시일

| | |
| --- | --- |
| 타입·실측 | `Int` · 8자리 `YYYYMMDD` · 20230227–20260805 |
| 의미 | **출시일.** 기본 인격 12종이 전부 `2023-02-27`(게임 정식 출시일)이다 |
| 교차대조 | assets `date` 와 **183/184 일치** |
| 변환 | `toIsoDate`(`src/text.ts:262`) — `20230227` → `2023-02-27` |
| 적재 | `identity.release_date` |
| 화면 | 상세 "출시일" |
| 함정 | **불일치 1건이 픽업 종료일이다** |

```
10116 LCE E.G.O:: 차원찢개
  mj      2026-08-05 (수)     ← 픽업 종료일. 스냅샷(07-25)보다 미래
  assets  2026-07-23 (목)     ← 실제 출시일

인격 출시 주기: 목요일 2주 간격
  06-11(목) → 06-25(목) → 07-09(목) → 07-23(목) → [08-06(목)]
```

`08-06` 갱신 하루 전이 `08-05` 다. 스냅샷 시점에 픽업이 진행 중이던 유일한 인격이다.

**결정 2026-07-29 — 미래 날짜는 보강 출처로 채운다**

```
updatedDate 를 ISO 로 바꾼 값이 dataset.snapshot_date 보다 미래이면
  → limbus-assets 의 date 를 쓰고 ctx.report.note 를 남긴다
```

`season` 결손 보강과 같은 패턴이다(ADR-04 2.3). 정본이 **줄 수 없는 값**만 보강 출처에서
받으므로 원칙 6(정본 값을 다른 출처로 덮지 않는다)을 지킨다. 현재 해당하는 것은 `10116` 1건이며,
스냅샷 날짜는 `dataset` 테이블에 이미 있어 가드 기준이 확보돼 있다.

"두 출처가 다르면 항상 assets 우선" 이나 "출시일은 항상 assets" 로 넓히지 않는다. 전자는 정본
뒤집기에 가깝고 후자는 원칙 6 위반이다.

E.G.O 쪽에는 성격이 다른 오류가 하나 있다 — `20306` 전기울음(돈키호테)이
mj `2023-04-11` · assets `2024-04-11` 로 **연도 오타**다. 시즌 4는 2024년이고
같은 날 나온 짝 3종은 mj도 2024로 적혀 있다.

## 함정 요약

1. `name` 은 수감자명, `title` 이 인격명 — 뒤집혀 있다
2. 인격명은 유일하지 않다 (`LCB Sinner` 12건). 수감자명과 짝지어야 구별된다
3. `star` → `rarity` → `0/00/000` 으로 한 개념에 이름이 셋
4. `season` 한 컬럼에 시즌 번호와 발푸르기스 회차가 섞여 있고 화면에 `S9104` 로 나간다
5. `10116` 의 `updatedDate` 는 출시일이 아니라 픽업 종료일이다
6. `keywords` · `associations` 는 assets와 **층·범위가 달라** 정본이 아니다
7. `speed` 는 동기화 4단계 값이지 1단계가 아니다
8. `stagger` 는 길이가 인격마다 다르다
9. `resists` 는 값이 클수록 나쁘다(배수)
10. `atkTypes` 라는 이름이 코드에서 다른 단위로 재사용된다
