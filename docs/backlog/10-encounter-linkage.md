# 인카운터를 가리키는 두 체계가 이어지지 않는다

> 상태: **여전히 미해결** · 신규 DB 가 기록
> 데이터 마스터북 인카운터 편 회차 2에서 확인했다.

## 0. 여전히 미해결 — 다만 기록됐다 (2026-08-01)

신규 3스키마 DB 도 **잇지 못했다.** `data/` 전역에 연결표가 없다는 판정이
그대로다.

```
mj packs_detail 의 5개 풀    7자리 숫자 2,525종
assets encounters/*.json     UUID + "md|canto-1-1"  251개
                             ↕  연결표 없음
```

다만 **미해결이라는 사실이 DB 안에 기록됐다.**

```sql
SELECT reason, evidence FROM canonical.field_gap WHERE field = 'battlePool';
```

검증에도 박혀 있어(`v2:verify:canonical`) 나중에 연결표가 생기면 그 검사가
알려준다.

## 1. 증상

거울 던전 맵 생성 규칙이 뽑는 **전투 2,525종의 정의가 리포에 없다.**

```
limbus-data-mj  packs_detail.json 의 bossPool·battlePool·abBattlePool·
                hardBattlePool·hardAbBattlePool          7자리 숫자 2,525종

limbus-assets   encounters/*.json                        UUID + "md|canto-1-1" 문자열 키 251개
```

**두 체계를 잇는 표가 어디에도 없다.**

## 2. 탐색 범위

```
assets 인카운터 251개 파일에서 7자리 숫자        0건
loc-* Enemies 43파일에서 mj 풀 id               0건
data/entities/ 전역에서 mj 풀 id 를 갖는 파일    E.G.O 스킬과 번호 공간이 겹칠 뿐
```

겹친 23건은 `egos_detail.json` · `skills.json` 의 **E.G.O 스킬 id** 다.

```
mj 전투 풀 앞자리   206xxxx 2,388 · 207xxxx 133 · 900xxxx 4
E.G.O 스킬          2060811(홍루) · 2070811(히스클리프)
```

인격 편 회차 4의 **번호 공간 충돌**과 같은 현상이며 **연결이 아니다.**

## 3. 지금은 영향이 없다

우리 파이프라인은 인카운터를 적재하지 않는다. `Encounter` 모델이 없고
거울 던전 맵을 생성하지도 않는다.

**영향이 생기는 시점** — 아래 중 하나를 하려 할 때다.

- 「이 테마 팩에서 어떤 적이 나오는가」를 보여주기
- 편성 추천에 **적의 저항**(회차 1의 10축)을 반영하기
- 층별 난이도를 실제 적 스탯으로 계산하기

## 4. 메울 방법

| 방법 | 비용 | 확실성 |
| --- | --- | --- |
| 출처를 더 받는다 (게임 덤프 계열) | 중 | **높음** — `04-data-inventory.md` 의 `game-dump-2023-*` 2종이 후보 |
| assets 인카운터 251개를 팩과 이름·테마로 매칭 | 높음 | 낮음 — 2,525 대 251 이라 규모가 안 맞는다 |
| mj 풀을 포기하고 assets 만 쓴다 | 낮음 | 팩별 전투 풀을 잃는다 |

**251 대 2,525 는 규모가 다르다.** assets 는 대표 인카운터만 갖고 mj 는 노드 단위를
갖는 것으로 보인다. 같은 것의 두 표기가 아니라 **粒度가 다른 두 데이터**일 수 있다.

## 5. 미룬 이유

적재 계획에 인카운터가 없다. 마스터북이 「무엇이 없는지」를 기록하는 것이 목적이므로
**결손을 확정한 것으로 이 회차의 몫은 끝났다.**
