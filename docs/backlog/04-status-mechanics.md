# 상태 기믹이 별개의 축인데 어디에도 없다

> 상태: 엔진 배선 해소(Task 2·2b, 2026-07-28) / 인격 화면 독립 구획은 미착수(7절 항목 5, 화면
> 작업이라 4단계 이후로 남는다) / 전수 확인 2026-07-28
> 탄환과 보호는 키워드도 소속도 아닌 **제3의 축**이다. 엔진은 이제 이 축을 공급·조건 양쪽에서
> 다른 여덟 축과 같은 경로로 다룬다(아래 10절). 데이터는 전부 있었고, 담을 자리가 없던 것은
> 엔진 쪽이었다 — 이제 있다.

## 1. 축이 셋이다

인격을 서술하는 축을 지금까지 둘로 봤다 — 키워드(화상·출혈·…)와 소속(새벽 사무소·엄지·…).
**셋이다.**

| 축 | 무엇 | 게임이 부르는 이름 | 우리 자리 |
| --- | --- | --- | --- |
| 키워드 | 기프트 분류 10종 | `EgoGiftCategory` 12종 | `keyword` 테이블 |
| 소속 | 인격 태그 93종 | `tags` (혼재, [01](01-identity-tags.md)) | `affiliation` 테이블 |
| **상태 기믹** | **탄환 · 보호** | 분류 파일 없음 | **없음** |

세 축은 성격이 다르다. 키워드는 기프트를 나누는 분류이고, 소속은 인격의 배경 태그이며,
상태 기믹은 **인격이 공급하고 기프트가 조건으로 참조하는 자원**이다.

## 2. 전수 확인 — 놓친 것은 둘뿐이다

기프트 발동 토큰 150종이 참조하는 기믹을 전부 뽑아 분류했다.

| 분류 | 개수 | 엔진 처리 |
| --- | ---: | --- |
| 우리 상태 축 8종 (화상·출혈·진동·파열·침잠·호흡·충전·혈사) | 8 | 전부 참조되고 전부 잡힌다 |
| 죄악 | 7 | `SIN_SKILL` · `RESONANCE` |
| 공격 타입 | 3 | `ATTACK_TYPE_USED` |
| 방어 (가드·회피·반격) | 3 | 상황성 빈도로 근사 |
| 코인 구성 · 공격 가중 | 6 | 상황성 빈도로 근사 |
| 체력계 (HP · SP · 속도) | 3 | 상황성 빈도로 근사 |
| **분류 밖** | **2** | **탄환 · 보호** |

**우리 상태 축 8종은 하나도 남김없이 기프트 조건에 등장한다.** 축 선정 자체는 헛돌지 않았고
빠뜨린 것이 둘이다.

## 3. 탄환 (Ammo)

| | |
| --- | --- |
| 상태 | `Bullet`(탄환) + 파생 — `BulletGodok` 탄환-고독 · `BulletPropellant` 호표탄 · `BulletPropellantSpecial` 맹호표탄 · `AccelBullet` 가속탄 · `BulletLament` 산나비·죽은나비 |
| 인격 | **13명** |
| 기프트 조건 | 8건 — `Ammo Skill Used` 7 · `Allies have Ammo Skill` 1 |
| 기프트 효과 | 없음 |
| 지금 | 공급을 세지 않고 고정 빈도 `0.2` |

보유 인격 — 엄숙한 애도(10110) · LCCB 대리(10406 · 10804) · 잔향・외로움(10414) ·
동부 엄지 카포IIII(10512) · 호넷【변조】(10514) · 마침표 사무소 대표(10611) ·
R사 제4무리 토끼팀(10703) · 마침표 사무소 해결사(10711) · 거미집 엄지 아비(10916) ·
동부 엄지 솔다토II(11013) · LCA 우제트 선봉 3팀장(11114) · 쌍갈고리 해적단 부선장(11207)

## 4. 보호 (Shield)

| | |
| --- | --- |
| 상태 | `Protection`(보호) · `BurstProtection`(파열 보호) |
| 인격 | **15명** (+ 파열 보호 2명) |
| 기프트 조건 | 2건 — `Allies with Shield` · `Enemies with Shield` |
| 기프트 효과 | **10건** — `Gain Shield` |
| 지금 | 공급을 세지 않고 고정 빈도 `0.45` |

**탄환과 성격이 하나 다르다.** 보호는 조건이자 **효과**다. 즉 기프트가 보호를 주고 다른
기프트가 보호를 조건으로 켠다. 축으로 올리면 그 고리에서 **기프트 간 시너지가 창발**하는데
지금은 끊겨 있다.

## 5. 화진 덱 검증에 걸린다

**검증 대상 7명 중 3명이 탄환 공급자다** — 10512 · 10916 · 11013, 전부 엄지 소속이다.
`06-recommendation-engine.md` 8절이 보고한 축 순위는 탄환 축이 없는 상태에서 잰 값이다.

## 6. 어디에 담고 어떻게 보일 것인가

**키워드에도 소속에도 넣지 않는다.** 별개 축이므로 별개로 담고 별개로 보인다.

| | 방향 |
| --- | --- |
| 데이터 | `status_mechanic` 같은 별도 테이블. 인격–기믹 관계도 별도 |
| 인격 상세 | 키워드·소속과 나란한 **독립 구획**. 섞어 놓으면 셋의 성격 차이가 사라진다 |
| 인격 목록 | 필터 축을 따로 둔다 |
| 엔진 | `StatusKey` 에 더한다. 그러면 공급·조건·시너지가 다른 여덟과 같은 경로를 탄다 |

게임도 이 셋을 한 분류로 묶지 않는다 — `EgoGiftCategory.json` 은 키워드만 정의하고
탄환·보호에는 분류 파일이 없다.

## 7. 고치는 법

어휘 네 곳과 화면이다.

1. `StatusKey` 에 `ammo` · `shield` 를 더한다.
2. `load.ts` 의 `STATUS_MATCH` 에 매칭을 더한다. **파생 상태를 어디까지 셀지 확인이 필요하다** —
   호표탄이 탄환과 같은 자원인지, 파열 보호가 보호와 같은지는 게임 사양을 봐야 한다.
3. `Ammo Skill Used` · `Allies with Shield` 등을 `SKILL_SUPPLIES` 로 옮긴다.
4. `EFFECT_W` 의 `SHIELD` 는 이미 있다. 효과 쪽은 손댈 것이 없다.
5. 인격 화면에 독립 구획을 만든다.

## 8. 왜 지금 미루는가

3단계의 목적은 **엔진 기반이 도는지 확인하는 것**이었고 그것은 확인됐다.
축을 둘 더하면 검증 수치가 전부 바뀌어 무엇 때문에 바뀌었는지 흐려진다.

`06-recommendation-engine.md` 10절의 알려진 근사에 적어, 검증 보고가 이 결손을 감추지 않게 했다.

## 9. 근본 원인

`StatusKey` 여덟은 **실측 토큰에서 뽑은 것이 아니라** 키워드 10종에서 출발해 혈사를 더한
것이다. 축을 데이터가 아니라 기존 분류에서 유도했고, 그래서 게임이 분류 파일을 주지 않는
기믹(탄환·보호)이 통째로 빠졌다.

이 문서의 2절이 그 전수 확인이며, **같은 방식으로 확인한 결과 더 이상은 없다.**

## 10. 해소 — 엔진 배선 (Task 2·2b, 2026-07-28)

7절의 고치는 법 5개 항목 중 엔진 몫 넷을 배선했다. 화면 몫(항목 5, 인격 상세 독립 구획)은
`app/**`·`components/**` 를 건드리는 별도 작업이라 이번에 포함하지 않는다 — 여전히 미착수다.

| 항목 | 상태 |
| --- | --- |
| 1. `StatusKey` 에 `ammo`·`protection` 추가 | 했다(`lib/engine/vocab.ts`) |
| 2. `load.ts` `STATUS_MATCH` 에 탄환·보호 패턴 추가 | 했다(`Bullet` 계열 → `ammo`, `(Burst)?Protection` → `protection`) |
| 3. `Ammo Skill Used`·`Allies with Shield` 등을 `SKILL_SUPPLIES` 로 옮김 | 했다 — 기프트 조건이 이제 이 축을 실제로 읽는다 |
| 4. `EFFECT_W` 의 `SHIELD` | 원래 있던 그대로, 손대지 않았다 |
| 5. 인격 화면에 독립 구획 | **미착수.** 화면 작업, 이번 범위 밖 |

3·4절이 "지금: 공급을 세지 않고 고정 빈도 0.2/0.45" 라 적어둔 근사는 더 이상 맞지 않는다 —
지금은 실제 공급 인원수를 센다. 다만 이 표는 당시 조사 기록이라 그대로 남기고, 최신 값은
여기 10절에 적는다.

**골든 회귀로 확인한 변화(전수)**: 화진 덱(`06-recommendation-engine.md` 8절)의 팩 1017 후보
중 기프트 **9145(찢어진 밴돌리어)** 하나의 `ammo 공급 3명` 조건이 새로 켜져 그 기프트 한계
효용이 0.119→0.256 로 오르고 팩 1017 점수가 72.704→72.837 로 움직였다. 같은 원인으로 tremor
키워드 기프트 **9283(상납된 시가)**·**9828(카포를 위하여)** 두 건도 `ammo` 조건이 새로 켜져
축3 tremor 평균이 0.393→0.396 로 올랐다. 골든이 실제로 잡아낸 변화는 이 셋뿐이다 — 탄환·보호
조건을 참조하는 기프트가 이 셋 말고도 더 있지만(예: 9226·9771, poise 키워드), 이 화진 덱의
팩 1017 후보군 밖에 있거나 골든이 상위 3종 팩·상위 3종 축만 기록해 드러나지 않을 뿐이다. 5절이
말한 "탄환 축이 없는 상태에서 잰 값"은 이제 지난 이야기다.

**증명하지 못한 것도 있다**: 화진 골든 덱은 편성 7명이 곧 출전 7명이라(대기 없음), 소속 조건의
판정 범위(편성/출전, Task 3·4) 분기는 이 시나리오에서 수치에 영향을 못 준다. `RunState` 를
만드는 자리 어디도 아직 편성과 출전에 다른 배열을 넘기지 않기 때문이다
(`06-recommendation-engine.md` 12절 참조). 탄환·보호 축 자체는 골든이 증명했지만, 판정 범위
개선은 단위테스트로만 증명됐다는 뜻이다 — 둘을 섞어 말하지 않는다.
