# 2단계 웹 화면에 남은 구멍

> 상태: 미착수 / 확인 2026-07-27
> 47테이블 전수 대조와 상세 1,734쪽 전수 요청으로 확인한 잔여 항목이다.
> 2단계 성공 기준은 충족한다 — 데이터는 전부 보인다. 아래는 정밀도의 문제다.

검증 방법과 결과는 다음과 같다.

| 검사 | 결과 |
| --- | --- |
| 47테이블 → 화면 도달 (49개 검사 × 한/영) | 98건 전부 통과 |
| 상세 전수 (867 엔티티 × 2로케일) | 1,734건 전부 HTTP 200, 오류 흔적 0 |
| 페이지네이션 | 기프트 456 · 상태 1,472 전부 도달 |

## 1. `MirrorDungeon.name` 이 스키마에 없다

`02-data-model.md` 3.8 이 `name` 을 정의했으나 `schema.prisma` 의 모델에는
`version` · `totalFloors` · `baseFloors` 뿐이고 텍스트 테이블도 없다.

**원본에는 있다.** `data/entities/mirror-dungeon/loc-{ko,en}/MirrorDungeonName.json` 의
`mirrordungeon_name_7` 이며 id 접미사가 버전 번호와 대응한다.

| 버전 | 한국어 | 영어 |
| --- | --- | --- |
| MD7 (현행) | 이름과 거미의 거울 | Mirror of Names and Spiders |

그 결과 `/[locale]/dungeon` 화면이 내부 키 `MD7` 을 그대로 노출한다.
`05-ui-foundation.md` 10절이 "화면에는 명칭을 쓰고 내부 키를 노출하지 않는다"고 정했으므로
이 화면은 아직 그 규정을 지키지 못한다.

고치려면 `MirrorDungeon` 에 텍스트 테이블을 붙이고 변환기가 `MirrorDungeonName.json` 을 읽게 한다.

## 2. 질의하지만 화면에 내지 않는 컬럼 3개

| 컬럼 | 값의 분포 | 비고 |
| --- | --- | --- |
| `skill.tier` | 1:403 · 2:196 · 3:236 · 4:1 | 스킬 카드에 표시하지 않는다 |
| `passive.condType` | `owned` 339 · `res` 146 · null 105 | 발동 조건의 종류 |
| `sin_info.attribute` | CRIMSON · SCARLET · AMBER · SHAMROCK · AZURE · INDIGO · VIOLET | 죄악별 색 이름. 디자인 단계에서 쓸 값이다 |

`descRaw` 는 의도적으로 표시하지 않는다(파싱용 원문, ADR-03 3.3).
`gift.keywordId` 는 조인 키이며 표시형(`keyword.name`)이 나오므로 누락이 아니다.

## 3. 인카운터 이름이 없다

`pack_boss_encounter` 75행이 팩 상세에서 **원시 id 문자열로** 노출된다.
인카운터 엔티티가 스키마에 없어 이름을 붙일 수 없다.

원본에는 인카운터 380개가 있으나 1단계 적재 범위에 넣지 않았다
(`01-data-source.md` 1절이 대상을 네 엔티티와 부속 데이터로 한정했다).

## 4. 수감자 전용 화면이 없다

수감자 12명은 인격·E.G.O 목록의 필터 칩과 상세의 라벨로만 등장한다.
`sinner` · `sinner_text` 데이터 자체는 화면에 도달하므로 누락은 아니나,
수감자를 축으로 인격과 E.G.O 를 함께 보는 화면이 없다.

`05-ui-foundation.md` 4.3 이 E.G.O 를 인격 상세에 담지 않기로 하면서
`/egos` 의 수감자 필터로 잇기로 했다. 수감자 화면을 만든다면 그 자리가 자연스럽다.

## 5. 스킬 아이콘 13종의 대체 표시

원본에 파일이 없는 인격 스킬 아이콘이 13종이다(`04-data-inventory.md` 7절).
현재는 점선 사각형만 나온다. 대부분 이름 없는 반격·조건부 발동 스킬이며
게임에서 기본 아이콘을 공유하는 것으로 보이나 확정되지 않았다.

id 는 `1000104` · `1021207` · `1041205` · `1041206` · `1071006` · `1071506` · `1071507` ·
`1081405` · `1101205` · `1101206` · `1111510` · `1111511` · `1121607` 이다.

## 6. Next.js 전이 의존의 취약점을 `overrides` 로 막고 있다

`npm audit` 이 postcss 와 sharp 에서 high 3건을 보고했다. 둘 다 Next 의 전이 의존이며
Next 가 postcss 를 **정확한 버전으로 고정**해 패치본이 올라오지 못한다.
Next 15 로 내려도 같은 postcss 8.4.31 을 고정하고 sharp 는 오히려 낮다(`^0.34.3`).

`package.json` 의 `overrides` 로 postcss `^8.5.23` · sharp `^0.35.3` 을 강제해 현재 0건이다.

**Next 가 이 의존을 갱신하면 `overrides` 를 걷어내야 한다.** 방치하면 Next 가 요구하는
버전과 어긋날 수 있다. 배포를 결정하는 시점에 함께 본다.

## 7. 시각 디자인이 반영되지 않았다

`app/globals.css` 의 색·타이포는 배치 확인용 중립값이다.
`05-ui-foundation.md` 8절이 정한 게임 세계관 톤은 아직 적용하지 않았다.
레이아웃 골격만 이전 프로토타입(`limbus-mirror-tracker-v1`)에서 가져온 상태다.
