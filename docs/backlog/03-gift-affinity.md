# 기프트의 색 속성을 어디에 쓰는지 모른다

> 상태: 표기 정정 완료 2026-07-27 / 용도 확인 미착수
> 원본은 색(`attributeType`)으로 기록하는데 추출기들이 죄악으로 바꿔 놓았다.
> 우리는 원본 어휘를 그대로 담고 화면에서는 쓰지 않는다.

## 1. 무엇이 문제였나

E.G.O 기프트 456종 전부가 **죄악 속성**을 갖는 것으로 적재되어 있었고 화면이 그것을
등급·키워드와 같은 무게로 표시했다. 게임은 기프트에 죄악을 표기하지 않는다.

## 2. 원본은 색으로 기록한다

`limbus-data-mj` 의 `gifts_detail.json` 이 게임 값을 그대로 담고 있다.

```json
{ "id": 9001, "attributeType": "CRIMSON", "keyword": "Combustion" }
```

값은 일곱 색이다 — `CRIMSON` · `SCARLET` · `AMBER` · `SHAMROCK` · `AZURE` · `INDIGO` · `VIOLET`.

**죄악에도 같은 색이 배정되어 있다**(`sins.json` 의 `attribute`). 그래서 추출기들이
색을 죄악으로 되바꿔 놓았다.

| 단계 | 값 |
| --- | --- |
| 게임 원본 (`gifts_detail.json`) | `attributeType: "CRIMSON"` |
| `limbus-assets` | `affinity: "wrath"` |
| `limbus-data-mj` 요약 (`gifts.json`) | `sin: "wrath"` |
| 우리 1단계 적재 (2026-07-26) | `gift.affinity: wrath` |

색→죄악 변환이 `limbus-assets` 의 `affinity` 와 **437/441** 일치한다. 두 추출기가
독립적으로 같은 변환을 한 것이며, 어긋나는 4건은 `9038` · `9111` · `9404` · `9707` 이다.

**죄악과 색이 대응한다는 것 자체는 사실이다.** 키워드도 같은 색 체계를 쓴다.
문제는 원본이 색을 담는데 우리가 죄악을 담았다는 것 — 해석을 데이터에 박아 넣었다.

## 3. 게임이 플레이어에게 주는 분류는 키워드다

로컬라이즈 원문에 `EgoGiftCategory.json` 이 있고 12종을 정의한다.

```
Combustion 화상 · Laceration 출혈 · Vibration 진동 · Burst 파열
Sinking 침잠 · Breath 호흡 · Charge 충전 · Random 무작위
Slash 참격 · Penetrate 관통 · Hit 타격 · None 범용
```

**색에는 이런 분류 파일이 없다.** 기프트 로케일 파일 30개 어디에도 없다.

## 4. 색이 무엇을 하는지는 확인하지 못했다

네 가지를 재봤고 전부 설명이 되지 않았다.

| 가설 | 결과 |
| --- | --- |
| 키워드의 다른 이름 | 아니다. `bleed` 52종이 여섯 색으로 흩어진다 |
| 설명문이 그 죄악을 다룬다 | 아니다. 456 중 75건. 완전 공명까지는 14건 |
| 합성 재료를 정한다 | 약하다. 재료쌍 185 중 48 (25.9%) |
| 팩을 나눈다 | 아니다. 큰 팩은 일곱 색을 다 담는다 |
| E.G.O 에서 물려받는다 | 아니다. 이름이 겹치는 기프트가 2종뿐이다 |

정석 짝(화상=분노색 · 출혈=색욕색 …) 쪽으로 **편향은 있다.** 게임이 효과에 어울리는 색을
칠했다고 보면 자연스러우나 확인된 것은 아니다.

카드 표시용 색이라는 것이 가장 그럴듯하다. 기프트 이미지가 프레임 없는 맨 아트워크이므로
게임이 색을 따로 입힐 자리가 있다. 다만 그 프레임 애셋을 찾지 못했다.

## 5. 한 조치

**원본 어휘로 되돌리고 화면에서 뺐다.**

| 대상 | 전 | 후 |
| --- | --- | --- |
| 스키마 | `gift.affinity: Sin` | `gift.attributeType: String?` |
| 값 | `wrath` | `CRIMSON` |
| 출처 | 정본의 변환된 값 | 보강 출처의 원본 값 |
| 목록 카드 | 죄악 배지 | 없음 |
| 목록 필터 | 죄악 축 | 없음 |
| 상세 | 죄악 행 | 없음 |
| 팩 상세 분포 | 죄악 분포 막대 | 없음 |

**15종은 비어 있다.** 보강 출처에 없는 기프트이며, 정본의 죄악 값을 색으로 되돌려
채우지 않는다 — 그것이 다시 해석을 넣는 일이다. 변환기가 리포트에 남긴다.

## 6. 남은 것

1. 게임 내 기프트 카드에 색이 실제로 어떻게 나오는가. 프레임 애셋이 있는가.
2. 상점·합성·보상에서 색으로 다루는 절차가 있는가.
3. **3단계 추천 엔진이 이 값을 쓸지.** 용도를 모르는 값을 점수화에 넣으면 근거를 설명할 수
   없고, 그것은 "추천은 근거를 제시한다"(`00-product.md` 3절)와 어긋난다.

## 7. 같은 종류의 위험

1단계가 원본 필드를 우리 어휘로 옮기면서 **해석을 데이터에 박아 넣은 사례**가 이것 하나라는
보장이 없다. `02-data-model.md` 3.5 는 이 필드를 `affinity | 죄악 속성` 으로 적으면서
근거를 남기지 않았다. 다른 필드에도 같은 검증 누락이 있을 수 있다.
[01-identity-tags.md](01-identity-tags.md) 가 같은 성격의 건이다 — `tags` 를 `소속` 으로 옮겼다.
