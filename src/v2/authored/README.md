# 저작 데이터

설명문에서 뽑아 **사람이 전건 검수한** 사실. 빌드는 이 파일을 읽고 설명문을
다시 파싱하지 않는다 — 그래야 결과가 고정되고 재현 가능하다(ADR-08).

## gift-ability.jsonl

한 줄이 능력 하나다. `(giftId, level, ordinal)` 이 열쇠다.

```json
{"giftId":"9262","level":0,"ordinal":0,"payload":{"timing":"none","unconditional":false,"refines":null,"sourceText":"약지 소속 인격 공격 종료시 …","conds":[{"group":0,"idx":0,"refKind":"association","refId":"RING_FINGER","op":"has","threshold":null,"scope":"roster","supply":"tag","slot":null,"runtime":false,"resonanceMode":null}]},"note":"두 문단 다 약지 소속을 요구한다"}
```

- `payload` 의 모양은 `src/v2/ability-payload.ts` 가 정하고 `validatePayload`
  가 지킨다. 심을 때 한 줄이라도 틀리면 **한 행도 안 심는다.**
- `sourceText` 는 설명문 문단 **원문 그대로**여야 한다. 요약하지 않는다 —
  검수와 재현의 근거다.
- `note` 는 검수자가 남기는 근거다. **지문에 안 들어간다** — 설명을 고치는
  것은 결과를 안 바꾸므로 재빌드를 요구할 이유가 없다.
- 검수가 끝나기 전에도 값이 나온다. 이 파일에 없는 기프트는
  `canonical.gift_ability` 행이 없고, 엔진은 그런 기프트를 **판정 보류**로
  다룬다(2단계). 회차가 진행될수록 판정이 정밀해진다.

### 알려진 근사

`9803` 의 「파열, 호흡을 부여하거나 획득하는 … 인격이 6인 이상」은 **두 축의
합집합 수**인데 모형이 합집합을 못 센다. 같은 group 에 `BURST ≥ 6` 과
`BREATH ≥ 6` 을 넣어 OR 로 근사했다 — 실제보다 빡빡하다. 같은 문형이 얼마나
더 있는지는 추출 회차가 알려준다.

## gift-rank.jsonl · gift-rank-candidates.json

기프트 순위 표본. `gift-rank.jsonl` 이 사람의 판정 **307줄**이고,
`gift-rank-candidates.json` 은 그 줄들이 무엇을 가리키는지 정하는 후보 셋이다 —
**덱 열하나**의 편성(출격 7 · 대기 5)과 축·공격 공급, 적합도의 분모인
`fieldSize`, 카드마다의 `fireable`·무더기(`stratum`)·합성 관계, 그리고 판정하는
사람이 읽을 `name`·`desc` 가 들어 있다.

**둘을 함께 커밋한다.** 판정 줄만 남기면 그 뜻을 정하는 것이 `/tmp` 에만 있어
재부팅이면 사라지고, 덱 공급이 7→6 으로 바뀌어도 giftId 는 그대로라 아무 경고
없이 저울추가 다른 수로 나온다.

**원문이 섞여 있다는 것을 분명히 해 둔다.** 편성·공급·`fireable` 은 `rank:deck`
이 DB 에서 셈한 파생이지만, `name` 과 `desc` 는 `canonical.gift_stage_text` 의
한국어 원문 그대로다 — 「우리 파생이라 원문이 아니다」가 아니다. 저작물 스냅샷
훅은 `data/` 아래만 보므로 걸리지 않고, 위 `gift-ability.jsonl` 이 `sourceText`
를 원문 그대로 커밋해 온 것과 같은 취급이다.

## 검수 절차

**456건 전건을 사람이 본다**(2026-08-11 사용자 확정). 페이지가 창구다.

```
에이전트  npm run gift:page      검수 페이지를 만들어 게시한다
사용자   페이지에서 절 단위로 훑으며 맞다/틀리다. 판정은 브라우저에 남는다
사용자   「내보내기」            verdicts.json 을 받아 전달한다
에이전트  npm run gift:import    progress.json 에 반영하고 틀리다를 읽는다
사용자   무엇이 틀렸는지 서술한다
에이전트  저작을 고치고 페이지를 다시 만든다
                              「틀리다」가 없어질 때까지 반복
```

1차를 「맞다 / 틀리다」 둘로 묶는 것이 요점이다. 「무엇이 틀렸나」를 456번
적게 하면 회차가 끝나지 않는다. 이유는 틀린 것에만, 그것도 에이전트가 먼저
읽은 뒤에 적는다.

진행 상황은 `gift-ability.progress.json` 이 기억하고 **함께 커밋한다** —
회차가 여러 날에 걸치고 기계가 바뀔 수 있다.
